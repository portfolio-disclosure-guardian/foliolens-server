# FolioLens 공시 Agent IA

| 항목 | 내용 |
|---|---|
| 문서 버전 | v2.0 |
| 갱신일 | 2026-08-03 |
| 문서 상태 | 평가 코어 우선 개정본 |
| 상위 문서 | `요구사항_정의서.md`, `기능명세서.md` |

## 1. IA 목적

이 문서는 FolioLens의 P1 질문 중심 웹에서 사용자가 질문하고, 답변의 사실·계산·근거·한계를 확인하는 화면 구조와 이동 흐름을 정의한다.

평가용 `GET /answer`에는 화면이 필요하지 않다. 웹은 P0 평가 코어의 품질을 보여 주는 시연 어댑터이며, 데이터 적재·파싱·검색·계산보다 먼저 구현하지 않는다.

## 2. 제품 단계와 화면 범위

### 2.1 P0 — 화면 없음

- 운영진이 평가 API로 자연어 질문을 전달한다.
- Spring 백엔드가 검색·계산·답변·검증을 수행한다.
- 웹 UI는 P0 완료 조건이 아니다.

### 2.2 P1 — 최소 시연 웹

필수 화면:

1. 질문 홈
2. 질문 결과
3. 근거 상세 드로어
4. 계산 상세 드로어
5. 데이터·분석 기준

2차 화면:

1. 공시 목록
2. 공시 상세
3. 후속 질문

### 2.3 P2 — 포트폴리오

- 로그인
- 보유 종목과 비중
- 투자 이유
- 개인화 질문과 공시 관련성

P2는 P0·P1과 분리해 후순위로 둔다.

## 3. 정보구조 원칙

### 3.1 질문 우선

첫 화면에서 포트폴리오 등록이나 대시보드를 요구하지 않는다. 사용자는 바로 질문할 수 있어야 한다.

### 3.2 결론 우선

답변 화면은 다음 순서를 따른다.

```text
직접 답변
→ 핵심 사실·비교
→ 계산
→ 정정·후속 이력
→ 사용 근거
→ 정보 한계
```

### 3.3 사실·계산·해석 분리

| 구분 | 의미 | UI 표현 |
|---|---|---|
| 공시 사실 | 원문에서 확인한 내용 | `사실` 라벨과 근거 |
| 백엔드 계산 | 검증 fact로 계산한 결과 | `계산` 라벨과 공식 |
| Agent 설명 | 사실·계산을 자연어로 해석 | `설명` 라벨과 조건 |
| 정보 한계 | 확인할 수 없는 내용 | `확인 필요` 또는 `한계` |

색상만으로 구분하지 않고 텍스트 라벨을 함께 표시한다.

### 3.4 근거는 핵심 기능

모든 핵심 주장과 수치에서 근거를 열 수 있어야 한다. 근거 상세에는 접수번호뿐 아니라 실제 문서·장·절·표·행과 문맥이 포함된다.

### 3.5 실패도 정상 상태

`PARTIAL`과 `UNANSWERABLE`은 시스템 오류가 아니다. 사용자가 무엇을 확인했고 무엇이 부족한지 이해할 수 있게 한다.

### 3.6 내부 추론 비공개

사용자에게 원시 chain-of-thought, 모델 프롬프트와 내부 디버그 로그를 표시하지 않는다. 필요한 경우 “기업 확인 → 공시 검색 → 수치 검증 → 계산”과 같은 구조화된 처리 단계만 보여 준다.

## 4. 핵심 사용자

| 사용자 | 핵심 작업 |
|---|---|
| 대회 평가자 | 질문을 제출하고 답변 정확성과 근거 확인 |
| 일반 웹 사용자 | 기업·기간·사건을 자연어로 질문하고 원문 확인 |
| 금융 검수자 | 수치·계산 기준·정정 반영 여부 확인 |
| 운영자 | 웹이 아닌 로그·DB·Actuator로 실행 상태 확인 |

관리자용 데이터 적재 화면은 P1 범위에 포함하지 않는다.

## 5. 전체 사이트맵

### 5.1 P1

```text
FolioLens
├─ 질문 홈                         /
├─ 질문 결과                       /questions/{runId}
│  ├─ 처리 상태
│  ├─ 직접 답변
│  ├─ 핵심 주장
│  ├─ 비교·계산
│  ├─ 정정·후속 이력
│  ├─ 근거 상세 드로어
│  ├─ 계산 상세 드로어
│  └─ 후속 질문
├─ 공시 탐색                       /disclosures
│  └─ 공시 상세                    /disclosures/{disclosureId}
└─ 데이터·분석 기준                /about/analysis-policy
```

### 5.2 P2

```text
FolioLens
└─ 포트폴리오                      /portfolio
   ├─ 보유 종목                    /portfolio/holdings
   ├─ 투자 이유                    /portfolio/theses
   └─ 개인화 질문                  /portfolio/questions/{runId}
```

## 6. 전역 내비게이션

### 6.1 데스크톱

```text
[FolioLens]  질문  공시 탐색  데이터·분석 기준                    [새 질문]
```

1차 시연에서는 `질문`과 `데이터·분석 기준`만 노출해도 된다. 구현되지 않은 메뉴를 비활성 상태로 미리 표시하지 않는다.

### 6.2 모바일

- 상단: 로고와 새 질문 버튼
- 나머지 메뉴: 메뉴 버튼
- 답변 중 새 질문은 언제든 접근 가능

### 6.3 공통 안내

화면 하단 또는 분석 기준 화면에 다음을 표시한다.

```text
FolioLens는 대회 제공 공시를 근거로 설명하며 투자 권유를 제공하지 않습니다.
```

## 8. QNA-001 질문 홈

### 8.1 목적

사용자가 서비스 설명을 길게 읽지 않고 바로 공시 질문을 시작하게 한다.

### 8.2 화면 구조

```text
┌────────────────────────────────────────────┐
│ 공시를 직접 찾지 말고 질문해 보세요        │
│ 기업·기간·수치를 찾아 근거와 함께 답합니다 │
│                                            │
│ [ 질문 입력............................. ] │
│ [질문하기]                                 │
│                                            │
│ 예시 질문                                  │
│ [시설투자] [공급계약] [기간 비교] [지분]   │
│                                            │
│ 데이터 범위: 70개 기업, 공시 4,204건       │
└────────────────────────────────────────────┘
```

### 8.3 입력 규칙

- 여러 줄 입력을 지원한다.
- 빈 질문은 전송하지 않는다.
- 최대 길이는 API 계약과 동일하게 한다.
- Enter와 버튼 모두 접근 가능하게 한다.
- 전송 중 중복 제출을 막는다.

### 8.4 대표 질문

초기 수직 슬라이스와 구현된 기능만 예시로 노출한다.

```text
SK하이닉스가 2024년 4월 발표한 신규시설투자의 투자금액과 목적은 무엇이야?
이 시설투자 금액의 자기자본 대비 비율을 다시 계산해줘.
```

지원하지 않는 기능을 대표 질문으로 먼저 보여 주지 않는다.

### 8.5 전송 후 분기

```text
질문 전송
→ 실행 생성 성공: /questions/{runId}
→ 기업 모호: 같은 결과 화면에서 기업 선택 요청
→ 요청 오류: 입력 아래 오류 문구
→ 서버 오류: 재시도 가능한 공통 오류
```

## 9. QNA-002 질문 결과

### 9.1 하나의 URL, 여러 상태

QNA-002는 실행 생명주기 전체를 담당한다.

```text
RECEIVED
PLANNING
VALIDATING_PLAN
RETRIEVING
CALCULATING
GENERATING
VALIDATING_ANSWER
COMPLETED
PARTIAL
UNANSWERABLE
FAILED
```

### 9.2 처리 중

표시 가능한 단계:

```text
질문의 기업과 기간을 확인하고 있습니다.
관련 공시를 찾고 있습니다.
공시의 수치와 근거를 검증하고 있습니다.
답변을 정리하고 있습니다.
```

표시하지 않는 내용:

- 원시 chain-of-thought
- 시스템 프롬프트
- 모델의 내부 토큰
- SQL과 stack trace
- 미검증 중간 답변

### 9.3 완료 화면 정보 순서

```text
1. 질문·답변 상태·데이터 기준시점
2. 직접 답변
3. 핵심 주장
4. 비교표 또는 계산 요약
5. 정정·후속공시 이력
6. 사용한 공시와 근거
7. 정보 한계
8. 후속 질문
```

### 9.4 데스크톱 레이아웃

```text
┌──────────────────────────────────────────────────────────┐
│ 질문 / 상태 / 기준시점                                  │
├───────────────────────────────────┬──────────────────────┤
│ 직접 답변                         │ 사용한 근거           │
│                                   │                      │
│ 핵심 주장                         │ [근거 1]             │
│ [사실] ... [근거 1]               │ [근거 2]             │
│ [계산] ... [계산 보기]            │                      │
│                                   │ 선택 근거 문맥        │
│ 비교·계산                         │                      │
│ 정정·후속 이력                    │                      │
│ 정보 한계                         │                      │
├───────────────────────────────────┴──────────────────────┤
│ 후속 질문 입력                                           │
└──────────────────────────────────────────────────────────┘
```

### 9.5 직접 답변

- 질문에 대한 결론을 먼저 보여 준다.
- 지나치게 긴 서론을 두지 않는다.
- 상태가 `PARTIAL`이면 직접 답변 옆에 부분 확인 라벨을 표시한다.

### 9.6 핵심 주장

```text
[사실] 투자금액은 5조 2,962억원입니다.              [근거 1]
[사실] 투자 목적은 생산능력 확충입니다.             [근거 2]
[계산] 자기자본 대비 비율은 21.7%입니다.            [계산 보기]
[설명] 공시는 해당 투자의 목적을 생산능력 확충으로 명시합니다.
```

규칙:

- FACT와 CALCULATION에는 반드시 클릭 가능한 연결이 있다.
- INTERPRETATION은 조건과 근거 사실을 함께 보여 준다.
- 접수번호만 나열하고 근거 연결을 대신하지 않는다.

### 9.7 비교

기업·기간·공시 기준을 표 상단에 명시한다.

| 항목 | 기준값 | 비교값 | 변화 |
|---|---:|---:|---:|
| 투자금액 | 2조원 | 2.4조원 | +4,000억원, +20.0% |

비교 기준이 다르면 계산하지 않고 차이를 경고한다.

### 9.8 정정·후속 이력

```text
최초 공시 → 정정 → 변경 → 해지/완료
```

각 사건에 다음을 표시한다.

- 접수일
- 공시명
- 사건 상태
- 바뀐 핵심 필드
- 근거
- 관계 확실성 또는 확인 필요

관계가 확정되지 않은 후보를 확정 타임라인처럼 표시하지 않는다.

### 9.9 사용한 공시

공시 카드 최소 정보:

- 기업명
- 공시명
- 공시 그룹·세부 유형
- 접수일
- 접수번호
- 정정 여부
- 사용한 근거 개수

### 9.10 정보 한계

한계가 있을 때만 표시하되 화면 하단에 숨기지 않는다.

예:

```text
확인한 범위: 대회 제공 공시, 2023-01-01~2026-03-31
확인하지 못한 항목: 실제 투자 집행률
이유: 제공 공시에 집행 실적이 포함되어 있지 않습니다.
```

### 9.11 후속 질문

후속 질문은 이전 실행의 기업·기간·선택 공시를 컨텍스트 후보로 전달한다. 사용자가 언제든 컨텍스트 칩을 제거할 수 있어야 한다.

```text
[SK하이닉스 ×] [2024년 4월 ×] [시설투자 ×]
[이 투자 기간은 얼마나 돼?................] [질문]
```

## 10. 답변 상태별 화면

### 10.1 `COMPLETED`

- 직접 답변 전체 표시
- 주장·계산·근거 정상 표시
- 데이터 기준과 후속 질문 제공

### 10.2 `PARTIAL`

```text
일부 항목만 공시에서 확인했습니다.
```

- 확인된 답변을 먼저 표시한다.
- 누락 항목과 이유를 별도 목록으로 표시한다.
- 확인되지 않은 값을 빈 표의 0으로 표현하지 않는다.

### 10.3 `UNANSWERABLE`

```text
제공된 공시에서 현재 주가를 확인할 수 없습니다.
확인 범위는 대회 제공 공시이며 실시간 시세 데이터는 포함하지 않습니다.
```

- 서버 오류 표현을 사용하지 않는다.
- 확인한 기업·기간·공시 범위를 표시한다.
- 외부 웹 검색 버튼을 자동으로 제공하지 않는다.
- 질문을 고칠 수 있는 예시가 있으면 제안한다.

### 10.4 `FAILED`

- 사용자용 오류 제목
- 간단한 원인 범주
- request ID
- 재시도 가능 여부
- 새 질문 또는 재시도 행동

내부 예외와 stack trace는 노출하지 않는다.

### 10.5 기업 모호성

기업 후보가 여러 개면 같은 결과 화면에서 선택을 요청한다.

후보 정보:

- 기업명·상장명
- 종목코드
- 시장
- 업종

사용자가 선택하면 원래 질문을 유지한 채 다시 실행한다.

## 11. EVD-001 근거 상세 드로어

### 11.1 열기

- 주장 옆 `근거 n` 칩
- 사용 공시 카드의 근거 목록
- 비교표의 값

### 11.2 정보 구조

```text
근거 헤더
├─ 기업명
├─ 공시명
├─ 접수번호·접수일
├─ 정정 여부
└─ 데이터 출처 CONTEST

원문 위치
├─ 실제 문서명
├─ 장·절 경로
├─ 표·행·열 또는 문단
└─ 파일 형식

근거 문맥
├─ 이전 문맥
├─ 강조된 사용 구간
└─ 다음 문맥
```

### 11.3 표 근거

숫자 셀만 보여 주지 않는다.

```text
단위: 원
투자금액(원)       5,296,200,000,000
자기자본(원)      24,427,000,000,000
자기자본대비(%)                  21.7
```

### 11.4 원문 보기

원문 렌더링이 안전하게 구현된 경우 해당 위치로 이동한다. 아직 원문 뷰어가 없다면 파일 다운로드를 노출하지 않고 구조화한 문맥과 위치를 제공한다.

원본 경로의 서버 절대경로를 사용자에게 노출하지 않는다.

## 12. CALC-001 계산 상세 드로어

### 12.1 정보 구조

- 계산명
- 공식
- 입력값과 단위
- 입력값별 근거
- 계산 전 기준 검증
- 원계산값
- 반올림·표시 규칙
- 최종 표시값
- 계산 규칙 버전

### 12.2 예시

```text
자기자본 대비 투자 비율

공식
투자금액 ÷ 자기자본 × 100

입력
투자금액: 5,296,200,000,000원  [근거 1]
자기자본: 24,427,000,000,000원 [근거 2]

결과
21.681...% → 소수점 첫째 자리 반올림 → 21.7%
```

입력 fact의 기업·기간·단위가 다르면 계산 결과 대신 계산 불가 사유를 표시한다.

## 17. API 연결

IA의 목표 연결은 다음과 같다. 세부 응답 필드는 API 명세를 따른다.

| 화면·행동 | 목표 API |
|---|---|
| 질문 제출 | `POST /api/v1/questions` |
| 질문 상태·결과 | `GET /api/v1/questions/{runId}` |
| 근거 상세 | `GET /api/v1/questions/{runId}/evidences/{evidenceId}` |
| 계산 상세 | `GET /api/v1/questions/{runId}/calculations/{calculationId}` |
| 공시 목록 | `GET /api/v1/disclosures` |
| 공시 상세 | `GET /api/v1/disclosures/{disclosureId}` |
| 분석 기준 | `GET /api/v1/meta/analysis-policy` |

평가 API는 화면과 직접 연결하지 않는다.

```http
GET /answer?question_id={questionId}&question={question}
```

평가와 웹 어댑터는 같은 질문 답변 코어를 호출한다.

## 19. 반응형 설계

### 19.1 데스크톱

- 최대 콘텐츠 폭 약 1200~1280px
- 답변과 근거를 2열로 볼 수 있음
- 긴 원문 문맥은 근거 패널 안에서 스크롤

### 19.2 태블릿

- 답변 1열
- 근거와 계산은 오른쪽 또는 전체 화면 드로어
- 비교표 가로 스크롤 허용

### 19.3 모바일

- 질문·답변 1열
- 근거·계산은 하단 시트 또는 전체 화면
- 직접 답변과 상태를 최상단에 유지
- 비교표는 항목 카드 또는 가로 스크롤
- 하단 시트가 열리면 포커스를 내부에 가둔다.

## 20. 접근성과 문구

### 20.1 접근성

- 모든 버튼·근거 칩을 키보드로 조작할 수 있어야 한다.
- 포커스 이동은 주장 → 근거 → 원문 문맥 순서와 일치해야 한다.
- 로딩·완료·오류 상태는 `aria-live`로 알린다.
- 색상 외에 텍스트와 아이콘으로 상태를 구분한다.
- 표에는 제목·머리글·단위가 있어야 한다.
- 드로어를 닫으면 원래 열었던 요소로 포커스를 돌린다.

### 20.2 권장 문구

| 상황 | 문구 예 |
|---|---|
| 검색 중 | 관련 공시를 찾고 있습니다. |
| 사실 | 공시에서 확인한 내용입니다. |
| 계산 | 확인한 수치에 공식을 적용한 결과입니다. |
| 부분 답변 | 일부 항목만 공시에서 확인했습니다. |
| 답변 불가 | 제공된 공시에서 확인할 수 없습니다. |
| 비교 불가 | 값의 기간 또는 기준이 달라 직접 비교하지 않았습니다. |
| 투자 판단 요구 | 공시 사실과 확인 조건을 중심으로 설명합니다. |

### 20.3 금지 문구

- 확실히 오릅니다.
- 반드시 매수해야 합니다.
- 하락 확률은 N%입니다.
- 목표주가는 N원입니다.
- AI의 정답입니다.

- [ ] 구현된 기능과 데이터 범위를 정확히 안내하는가?

- [ ] 직접 답변이 가장 먼저 보이는가?
- [ ] 사실·계산·설명·한계가 구분되는가?
- [ ] `PARTIAL`과 `UNANSWERABLE`이 오류와 구분되는가?
- [ ] 비교 기준과 단위가 보이는가?

### 근거와 계산

- [ ] 모든 핵심 사실과 수치에 근거 또는 계산 링크가 있는가?
- [ ] 근거에서 접수번호·문서명·원문 위치와 문맥을 확인할 수 있는가?

- [ ] 계산에서 입력·공식·반올림·입력 근거를 확인할 수 있는가?

- [ ] 투자 권유와 가격 예측 표현이 없는가?

### 반응형·접근성

- [ ] 모바일에서도 직접 답변과 근거를 확인할 수 있는가?

- [ ] 상태가 색상 외 텍스트로 전달되는가?

## 23. P2 포트폴리오 방향

P2를 구현할 때도 질문 결과의 기본 구조를 바꾸지 않는다.

```text
일반 공시 답변
└─ 내 포트폴리오와의 관련성
   ├─ 보유 종목 여부
   ├─ 보유 비중
   ├─ 연결된 투자 이유
   ├─ 관련되는 이유
   ├─ 관련되지 않는 이유 또는 불확실성
   └─ 다음 확인 지표
```

개인화 설명은 공시 사실처럼 표시하지 않으며 매수·매도 추천으로 변환하지 않는다.
