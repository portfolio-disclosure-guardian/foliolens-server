# 공시 분석유형 10: 계속기업·법률위험

> 공통 적용 규격: [공시 분석유형 00: 공통 Fact·근거·계산·골든 규격](./공시_분석유형_00_공통규격.md)

## 1. 유형의 범위와 데이터 현황

회사의 정상 영업·재무 존속에 영향을 줄 수 있는 법률·규제·영업중단 사건을 다룬다. 제공 데이터에서 직접 확인되는 주요사항보고서 세부유형은 소송 5건과 영업정지 1건이다. 회생·파산·부도·상장적격성 등은 데이터에 존재하는 경우에만 동일 구조를 확장한다.

공시 존재가 곧 회사 존속불가를 뜻하지 않는다. 사건의 행위, 절차단계, 회사 대응, 효력정지 여부와 결과를 분리한다.

대회 데이터 직접범위는 전체 4,204건 중 소송 5건과 영업정지 1건, 합계 6건으로 약 0.14%다. 회생·부도·은행거래정지·채권자관리·해산은 공식 공시구조에 대비한 조건부 확장으로 두며, 제공 원문이 없으면 평가 답변의 사실근거로 사용하지 않는다.

## 2. 지원 질문

- 어떤 소송·행정처분·영업정지 사건이 발생했는가?
- 청구·제재·영업정지 금액과 회사 규모 대비 비율은 얼마인가?
- 현재 효력이 발생했는가, 집행정지 신청 중인가?
- 회사는 항소·취소소송·집행정지 등 어떻게 대응하는가?
- 영업정지 대상 사업과 기간·매출 영향은 무엇인가?
- 판결·처분·정지결정·재개 등 후속 결과는 무엇인가?
- 이 사건만으로 계속기업 위험을 판단할 수 있는가?

위 목록은 요약이다. 질문을 문장 그대로 하드코딩하지 않고 다음 질문 의도를 Fact·상태·계산에 연결한다.

## 3. 사건·행위·결과의 구분

| 구분 | 뜻 | 예시 |
|---|---|---|
| 사건 유형(`event_type`) | 무엇에 관한 공시인지 | `LITIGATION` 소송, `BUSINESS_SUSPENSION` 영업정지, `INSOLVENCY` 지급불능, `REHABILITATION` 회생절차 |
| 사건 행위(`event_action`) | 이번 문서에서 무엇을 했거나 당했는지 | 제소, 피소, 판결, 처분결정, 집행정지 신청, 항소, 영업재개 |
| 절차 상태(`proceeding_status`) | 기준시점 현재 절차가 어디까지 갔는지 | 제1심 진행, 항소 중, 집행정지 인용, 확정 |
| 결과 코드(`result_code`) | 확인된 판단·결과가 무엇인지 | 인용, 기각, 일부인용, 취하, 화해, 처분취소, 미확정 |

코드를 일반 텍스트로 열거하는 이유는 백엔드가 서로 다른 원문 표현을 같은 검색 조건으로 다루게 하기 위해서다. 다만 원문에 없는 결과를 코드로 추정하면 안 된다.

### 3.1 사건유형 코드의 의미

| 코드 | 한국어 의미 | 적용 예 |
|---|---|---|
| `LITIGATION` | 소송·가처분·항소 등 법원·중재 사건 | 신주발행무효의 소 |
| `BUSINESS_SUSPENSION` | 회사 영업 전부·일부의 행정상 정지 | 특정 면허 영업정지 |
| `PAYMENT_DEFAULT` | 채무·어음·수표 등의 지급불이행 | 어음 부도 |
| `BANK_TRANSACTION_SUSPENSION` | 은행의 당좌거래 정지·금지 | 당좌거래정지 |
| `REHABILITATION` | 법원 회생절차 | 회생절차 개시신청 |
| `DISSOLUTION` | 회사 해산·청산 관련 사건 | 해산사유 발생 |
| `CREDITOR_MANAGEMENT` | 채권은행 공동관리·워크아웃 | 금융채권자 공동관리 |
| `OTHER` | 사건은 식별되지만 준비된 코드에 없음 | 기타 법률사건 |
| `UNKNOWN` | 원문 부족으로 사건유형 자체를 확인할 수 없음 | 내용 불명확 |

### 3.2 사건행위 코드의 의미

| 코드 | 한국어 의미 | 구분 기준 |
|---|---|---|
| `FILED` | 소장·항소장 등 사건서류가 실제 제출됨 | 계획과 구분 |
| `APPLIED` | 회생·집행정지 등 특정 절차를 신청함 | 결정·개시와 구분 |
| `DECIDED` | 법원·기관·회사가 결정을 내림 | 결과 내용은 별도 Fact |
| `COMMENCED` | 회생 등 절차가 공식 개시됨 | 신청만으로 부여 금지 |
| `CORRECTED` | 기존 공시 내용이 정정됨 | 사건이 새로 시작된 것이 아님 |
| `APPEALED` | 원심 결정에 대해 실제 불복절차를 제기함 | 항소계획과 구분 |
| `STAY_APPLIED` | 집행정지 신청이 접수됨 | 인용 여부와 구분 |
| `STAY_GRANTED` | 집행정지가 인용됨 | 신청만으로 부여 금지 |
| `STAY_DENIED` | 집행정지 신청이 기각됨 | 원문 기각 필요 |
| `WITHDRAWN` | 당사자가 신청·소송을 취하함 | 기각·각하와 구분 |
| `DISMISSED` | 법원 등이 신청·청구를 받아들이지 않음 | 결과코드의 기각·각하 세분 가능 |
| `TERMINATED` | 목표 달성 전 절차가 중단·폐지됨 | 정상완료와 구분 |
| `COMPLETED` | 예정 절차가 정상적으로 완료됨 | 회생 정상종결 등 |
| `OTHER` | 행위는 확인되나 준비된 코드에 없음 | 원문 보존 |
| `UNKNOWN` | 이번 문서의 행위를 확인할 수 없음 | 임의 추정 금지 |

### 3.3 소송 절차·역할·결과 코드

| 코드 집합 | 코드 | 의미 |
|---|---|---|
| 절차유형 | `CIVIL_ACTION` | 민사 본안소송 |
| 절차유형 | `PROVISIONAL_INJUNCTION` | 본안 전 행위금지 등을 구하는 가처분 |
| 절차유형 | `APPEAL` | 1심 판결·결정에 대한 항소 |
| 절차유형 | `SUPREME_COURT_APPEAL` | 항소심 결과에 대한 상고 |
| 절차유형 | `ADMINISTRATIVE_LITIGATION` | 행정처분을 다투는 소송 |
| 절차유형 | `CRIMINAL_PROCEEDING` | 형사절차 |
| 절차유형 | `ARBITRATION` | 법원이 아닌 중재기관 절차 |
| 당사자역할 | `PLAINTIFF` / `DEFENDANT` | 원고 / 피고 |
| 당사자역할 | `APPLICANT` / `RESPONDENT` | 신청인 / 피신청인 |
| 당사자역할 | `APPELLANT` / `APPELLEE` | 항소인 / 피항소인 |
| 당사자역할 | `CREDITOR` / `DEBTOR` | 채권자 / 채무자 |
| 결과 | `PLAINTIFF_WIN` / `DEFENDANT_WIN` | 원고 전부승소 / 피고 전부승소 |

| 결과 | `GRANTED` | 가처분·신청 인용 |
| 결과 | `REJECTED` | 청구·신청 기각 |
| 결과 | `DISMISSED` | 절차요건 등으로 각하 |
| 결과 | `SETTLED` / `WITHDRAWN` | 화해 / 취하 |
| 결과 | `UNKNOWN` | 결과 미발생·확인불가 |

같은 회사의 역할은 심급에 따라 바뀔 수 있다. 1심에서 `DEFENDANT`였던 회사가 직접 항소하면 항소심에서는 `APPELLANT`다.

## 4. 생성 방식과 원문 분리

| 방식 | 적용 |
|---|---|
| `DIRECT` | 사건명, 법원·기관, 청구취지, 회사 대응 원문 |
| `DIRECT_NORMALIZED` | 금액 원화, 날짜 ISO, 사건·행위·결과 코드 |
| `DERIVED` | 자기자본 대비 청구액, 매출 대비 정지대상 매출, 기간 |
| `LINKED` | 최초 소송과 판결·항소, 처분과 집행정지·영업재개 공시 연결 |

각 분류 Fact는 `.raw`에 공시 표현을, `.code`에 표준 코드를 저장한다. `기각`이 원문에 있으면 raw는 `DIRECT`, 코드 `DISMISSED`만 정규화다.

표의 `DIRECT`, `DERIVED`, `LINKED`는 설명용 축약이다. 실제 메타데이터는 공통 규격의 `DIRECT_RAW`, `TEXT_EXTRACTED`, `DIRECT_NORMALIZED`, `DERIVED_CLASSIFICATION`, `DERIVED_CALCULATION`, `LINKED_RESOLVED`를 사용한다. 사건번호·법원명처럼 원문에 있는 값은 `DIRECT_RAW`; 관련공시를 종합한 최신상태는 `LINKED_RESOLVED` 근거와 `DERIVED_CLASSIFICATION`의 조합이다.

## 5. Fact 사전

표의 Fact ID는 의미 단위 `factKey`다. `.raw`와 `.code`는 동일 Fact envelope의 원문 표현과 표준 분류를 구분한다. 접미사가 없는 날짜·금액 Fact도 `rawValue`, `normalizedValue`, 근거를 함께 저장하며, 후속공시로 얻은 상태는 출처 문서와 기준시점을 기록한다.

## 6. 결정적 계산 규칙

| 계산 ID | 공식 | 의미 | 의미하지 않는 것 |
|---|---|---|---|
| `CLAIM_EQUITY_RATIO_CHECK` | `청구금액 ÷ 자기자본 × 100` | 자기자본 대비 금전청구 규모 | 패소확률·최종손실 |
| `SUSPENDED_SALES_RATIO_CHECK` | `정지대상 매출 ÷ 회사 매출 × 100` | 과거 매출 기준 대상 사업 비중 | 같은 비율의 미래 매출 감소 확정 |
| `SUSPENSION_DURATION_DAYS` | `종료일 − 시작일 + 1` | 달력 기준 예정 정지기간 | 행정법상 산입방식과 다를 수 있음 |

청구금액, 처분금액, 충당부채, 실제 지급액은 서로 다른 개념이다. 법적 결과와 확률을 백엔드가 추정하지 않는다.

| 대응 질문 | 계산 | 계산 목적 | 허용 해석 | 금지 해석 |
|---|---|---|---|---|
| 자기자본 대비 청구규모는? | `CLAIM_EQUITY_RATIO_CHECK` | 공시 표시비율 산술검증 | 금전청구액의 상대규모 | 패소확률·최종손실 |
| 대상 매출이 전체의 몇 %야? | `SUSPENDED_SALES_RATIO_CHECK` | 동일 기간·회계기준 매출비율 검증 | 과거 매출 기준 대상범위 비중 | 동일 비율 미래매출 감소 |
| 정지기간은 며칠이야? | `SUSPENSION_DURATION_DAYS` | 달력상 예정기간 참고 | 시작·종료일 기준 일수 | 법령상 일수 산입 확정 |
| 사건금액이 얼마나 바뀌었어? | `EVENT_AMOUNT_CHANGE_RATE` | 정정 전후 동일 금액 변화 | 공시금액 증감 | 위험·패소 가능성 증감 |
| 현금에 비해 노출액이 커? | `RISK_AMOUNT_CASH_RATIO` | 사건금액과 최신 현금성자산의 상대규모 | 단순 비교비율 | 지급확정·유동성위기 |

계산 전 통화·단위, 기준일, 연결/별도, 기간, 분모 0 여부를 검사한다. 공시된 비율과 재계산값은 서로 덮어쓰지 않는다. 비금전 소송에는 청구금액 0을 넣지 않고 `NOT_APPLICABLE`로 처리한다.

### 6.2 최소 원문 근거와 답변 상태

사건유형·행위에는 제목·본문, 기관·사건번호에는 원문 표, 청구에는 청구취지·금액·통화, 영업정지에는 대상범위·사유·기간·매출표, 집행정지에는 계획·접수·결정 각각의 문장, 결과에는 판결·결정·확정 또는 후속공시를 연결한다.

| API 상태 | 판정 기준 |
|---|---|
| `COMPLETED` | 질문에 필요한 사건·행위·단계·금액 또는 범위·근거·기준시점이 모두 확인됨 |
| `PARTIAL` | 사건은 확인되지만 최신단계·효력·결과 등 질문 필수항목 일부가 부족 |
| `UNANSWERABLE` | 제공 공시에 질문 핵심정보가 없음 |
| `FAILED` | 검색·파싱·연결·계산 시스템 실패 |

소송이 진행 중이거나 결과가 불리한 것은 API `FAILED`가 아니다.

## 7. 상태와 답변 정책

- `FILED/NOTIFIED`: 소송 제기·처분 통지 확인.
- `PENDING`: 절차 진행 중이며 결과 미확정.
- `STAY_REQUESTED`: 집행정지를 신청했지만 결과 미확정.
- `STAY_GRANTED`: 효력정지 결정이 확인됨.
- `DECIDED_NOT_FINAL`: 판결·결정은 있으나 불복 가능.
- `FINAL`: 확정판결·확정처분 근거 확인.
- `RESUMED`: 영업재개가 확인됨.

“회사가 위험하다”, “파산할 것이다”가 아니라 사실·수치·현재 절차와 판단 한계를 답한다.

## 8. 골든 후보

아래 사례는 `C 검토대기`다. 처분·신청·법원 결정·확정판결을 별도 문서와 상태로 대조한 뒤 회귀테스트에 고정한다.

### GOLD-RISK-001: 대우건설 영업정지 처분

- 기대 접수번호: `20251216000493`
- 정지기간 원문: `2개월`
- 정지대상 매출액: `7,651,500,000,000원`(76,515억 원)
- 공시 매출 대비 비율: `72.84%`
- 예정 효력발생일: `2026-01-23`
- 회사 대응: 행정처분 취소소송 및 집행정지 신청 관련 원문을 별도 추출.
- 기대 표현: “영업정지 처분이 공시됐지만 실제 효력과 영업 영향은 집행정지 결정 및 대상 범위를 함께 확인해야 합니다.”
- 기대 사건 상태: 처분 공시와 예정 효력만 확인된 단계다. 처분 사실만으로 회사 전체 영업이 즉시 정지됐다고 판정하지 않는다.
- 기대 답변 상태: 처분 내용과 조건 질문의 Fact·근거가 모두 있으면 `COMPLETED` 가능.
- 치명적 오류: 72.84%를 미래 매출 감소율로 표현, 집행정지 신청을 인용으로 표현, 예정일을 실제 정지 개시일로 단정.

### GOLD-RISK-002: 고려아연 소송

- 기대 접수번호: `20240320001544`
- 검증 목적: 당사자 역할, 법원·사건번호, 청구취지·금액, 절차상태를 각각 분리한다.
- 치명적 오류: 소송 제기만으로 패소·손실을 확정하거나 청구액을 충당부채로 처리.

### GOLD-RISK-003: 고려아연 항소 후속공시

- 검증 목적: 동일 사건의 1심과 항소공시를 사건번호·당사자·청구내용으로 연결한다.
- 기대 분류: `event_type=LITIGATION`, `event_action=APPEALED`, `procedure_type=APPEAL`, 회사 역할은 해당 심급에서 `APPELLANT`, `stage=APPEAL_PENDING`, 결과 미확정이면 `outcome=UNKNOWN`.
- 기대 답변상태: 항소 제기·현재 단계 질문의 근거가 완전하면 `COMPLETED`.
- 치명적 오류: 항소 계획을 실제 항소접수로 처리하거나 1심의 `DEFENDANT` 역할을 항소심에도 그대로 사용.
- 승인상태: `C_REVIEW_PENDING`; 접수번호와 원문 위치는 대회 원문 대조 후 고정.

### GOLD-RISK-004: 사건번호 정정

- 검증 목적: 정정공시에서 사건번호만 바뀌었는지, 금액·청구·단계까지 바뀌었는지 `correction.changes[]`로 식별한다.
- 기대 처리: `event_action=CORRECTED`; 정정 자체로 새 사건을 만들거나 소송단계를 초기화하지 않는다.
- 치명적 오류: `is_correction=true`만 보고 모든 사건 Fact를 변경하거나 정정문을 독립 소송으로 생성.
- 승인상태: `C_REVIEW_PENDING`.

### 8.1 공통 치명적 오류

1. 소송 제기·가처분 신청만으로 패소·인용·손실을 확정.
2. 청구금액을 충당부채·실제 지급액·최종 손실액으로 처리.
3. 비금전 청구를 금액 0으로 저장.
4. 기각과 각하, 취하와 화해를 같은 결과로 무근거 통합.
5. 본안소송과 가처분을 같은 사건단계로 처리.
6. 회사 역할을 심급별로 갱신하지 않음.
7. 항소 계획을 실제 항소접수로 처리.
8. 집행정지 신청을 인용결정으로 처리.
9. 영업정지 대상 면허·사업부를 회사 전체 영업으로 확대.
10. 과거 대상매출 비율을 미래 매출감소율로 표현.
11. 예정 효력발생일을 실제 정지개시일로 단정.
12. 회생 신청·개시·인가·정상종결·폐지를 같은 상태로 처리.
13. 소송·영업정지 한 건만으로 파산·계속기업불가·주가하락을 단정.
14. 사건상태 `TERMINATED`나 불리한 결과를 API `FAILED`로 처리.
15. 최신 후속·정정공시를 확인하지 않고 과거 상태를 현재 상태로 답변.

## 9. B의 구현 순서

1. 제목·서식으로 사건 유형과 이번 행위를 별도로 분류한다.
2. 기관·사건번호·당사자역할을 먼저 추출해 후속공시 연결키로 사용한다.
3. 금액·날짜·기간·대상사업과 원문 근거를 저장하고 정규화한다.
4. 대응 “계획”, 신청 “완료”, 인용 “결정”을 서로 다른 상태로 관리한다.
5. 최초·판결·항소·집행정지·재개 공시를 연결해 기준시점 상태를 만든다.
6. 비율 계산은 동일 회계기준의 Fact가 있을 때만 수행한다.
7. C가 승인한 두 골든 후보로 예정/실제, 신청/인용, 청구액/손실액 분리를 검증한다.
