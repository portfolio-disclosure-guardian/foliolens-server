# 공시 분석유형 02: 신규시설투자

> 공통 적용 규격: [공시 분석유형 00: 공통 Fact·근거·계산·골든 규격](./공시_분석유형_00_공통규격.md)

| 항목 | 내용 |
|---|---|
| 문서 ID | `DISCLOSURE-ANALYSIS-02` |
| 내부 분석키 | `FACILITY_INVESTMENT` |
| 대상 | `exchange/신규시설투자등` 43건, 정정 15건 |
| 목적 | 투자대상·금액·목적·기간과 회사 재무규모 대비 부담을 근거로 답변 |

프로젝트 기존 명세가 `facility.*`를 사용하므로 이를 유지한다. 이는 C가 임의로 `investment.*`에서 변경한 것이 아니다.

43건은 전체 4,204건의 1.02%, `exchange` 1,469건의 2.93%이며 정정표시는 15건, 34.88%다. 문서 수가 가장 많아서 대표 질문이 된 것이 아니라 사실추출·계산·근거연결을 한 번에 검증하기 좋은 구조라서 첫 수직 구현 대상으로 선택했다.

기존 API의 핵심 Fact ID는 바꾸지 않는다. 아래의 `.raw_text`, `.normalized_value_krw`, `.value`는 해당 핵심 Fact에 붙는 저장 속성이다.

| 기존 핵심 Fact ID | 이 문서의 저장값 대응 |
|---|---|
| `facility.target` | `facility.target.raw`의 원문과 검증된 표시값 |
| `facility.amount` | `facility.amount.raw_text` + `facility.amount.normalized_value_krw` |
| `facility.equity_amount` | `facility.equity_amount.raw_text` + `facility.equity_amount.normalized_value_krw` |
| `facility.equity_ratio` | 공시값 `facility.disclosed_equity_ratio.value`; 재계산값은 별도 계산결과 |
| `facility.purpose` | `facility.purpose.raw` |
| `facility.start_date` | 원문 `facility.start_date.raw` + ISO 값 `.value` |
| `facility.end_date` | 원문 `facility.end_date.raw` + ISO 값 `.value` |
| `facility.decision_date` | 원문 `facility.decision_date.raw` + ISO 값 `.value` |

## 2. 생성 방식 검수

- 표의 투자구분·대상·금액·자기자본·비율·목적·날짜는 `DIRECT_RAW`다.
- 숫자·날짜·단위 형식 변환만 `DIRECT_NORMALIZED`다.
- `PLANNED`, `COMPANY_SHARE` 같은 금액성격과 현재 투자상태는 `DERIVED_CLASSIFICATION`이다.
- 부담률 등은 `DERIVED_CALCULATION`, 정정된 최신 계획은 `LINKED_RESOLVED`다.

## 3. Fact 사전

실제 `factKey`는 위 기존 핵심 ID처럼 의미 단위로 유지한다. 아래 `.raw`, `.raw_text`, `.value`, `.normalized_value_krw` 표기는 별도 factKey가 아니라 동일 Fact envelope의 `rawValue`, `rawUnit`, `normalizedValue`, `normalizedUnit` 속성을 설명하는 논리 경로다.

## 4. 계산

### 동일 공시 계산

| ID | 공식 | 말해주는 범위 |
|---|---|---|
| `FACILITY_EQUITY_RATIO_CHECK` | 투자금액÷자기자본×100 | 공시비율 검증 |
| `FACILITY_AMOUNT_CHANGE` | 정정 후−정정 전 | 계획금액 증감액 |
| `FACILITY_AMOUNT_CHANGE_RATE` | 변화액÷정정 전×100 | 계획금액 증감률 |
| `FACILITY_DURATION_DAYS` | 종료일−시작일+1 | 계획 투자기간 |
| `FACILITY_SCHEDULE_DELAY` | 정정 후 종료일−정정 전 종료일 | 일정 연장·단축 |
| `FACILITY_FX_CHECK` | 외화금액×공시환율 | 원화 환산 검증 |
| `FACILITY_COMPANY_SHARE_CHECK` | 총사업비×회사부담률 | 회사부담액 검증 |
| `FACILITY_DISCLOSURE_THRESHOLD` | 공시 자기자본비율−적용 기준비율 | 공시일 당시 의무기준 초과 정도의 규정 검토 |
| `FACILITY_CHANGE_THRESHOLD` | 절대 금액변화÷정정 전 금액×100 | 공시일 당시 변경기준 검토용 변화율 |

`FACILITY_EQUITY_RATIO_CHECK`는 투자금액과 자기자본의 통화·단위·기준시점·연결/별도 기준이 모두 맞을 때만 수행한다. 공시비율의 소수 자릿수를 `d`라 하면 원계산값을 `d`자리로 반올림해 공시값과 비교한다. 원계산값 기준 허용범위는 원칙적으로 `0.5 × 10^-d %p` 이내이며, 고정 `0.01%p`를 모든 문서에 일괄 적용하지 않는다.

### 정기공시 연결 확장계산

| 계산 | 대응 질문 | 허용 해석 | 금지 해석 |
|---|---|---|---|
| 투자금액÷현금성자산 | 현금에 비해 커? | 현재 현금 대비 총계획 규모 | 유동성 위기 단정 |
| 투자금액÷최근 12개월 영업현금흐름 | 영업현금으로 감당 가능해? | 최근 현금창출력 대비 규모 | 조달 가능 여부 확정 |
| 투자금액÷총자산 | 회사 규모에 비해 커? | 자산규모 대비 비중 | 성공·수익성 판단 |
| 투자금액÷최신 자기자본 | 현재 재무규모 기준 부담은? | 최신 자본 대비 참고 비율 | 공시 당시 공식비율 대체 |
| 투자금액÷계획기간(연) | 매년 얼마씩 투자하는 셈이야? | 균등배분 가정 참고값 | 실제 연도별 집행액 |

다년 총투자액을 한 해 현금흐름과 비교하면서 실제 연간 부담이라고 표현하지 않는다. NPV·IRR·회수기간은 미래현금흐름이 없으면 계산하지 않는다.

### 계산을 만든 이유와 답변 한계

| 계산 | 대응 질문 | 계산 결과의 의미 | 의미하지 않는 것 |
|---|---|---|---|
| 자기자본 대비 비율 | 공시비율이 맞아? | 공시 당시 사용한 자본 대비 계획금액 | 실제 집행률·수익성 |
| 현금 대비 투자규모 | 현금에 비해 커? | 현재 현금성자산 대비 다년 총계획액 | 유동성 위기 확정 |
| 영업현금흐름 대비 규모 | 영업현금으로 감당 가능해? | 최근 현금창출력 대비 총계획액 | 실제 조달 가능 여부 |
| 총자산 대비 규모 | 회사 전체 규모에 비해 커? | 자산규모 대비 계획금액 | 투자 성공·적정성 |
| 단순 연평균 계획액 | 매년 얼마씩 투자하는 셈이야? | 균등배분 가정 참고값 | 실제 연도별 집행액 |
| 공시·변경 기준 검토 | 의무기준을 넘었어? | 공시일 당시 규정에 입력값을 적용한 후보 판정 | 법 위반·공시 적정성 확정 |

규정 계산은 시장, 대규모법인 여부, 공시일 당시 규정 버전이 모두 확인될 때만 실행한다. 최신 규정을 과거 공시에 소급하지 않는다.

## 5. 근거·상태·표현 정책

- 핵심 8개 Fact 각각에 표 행·열·단위·주석 근거를 연결한다.
- 투자목적은 회사가 밝힌 원문 범위만 답하고 성장성·수익성 전망으로 확대하지 않는다.
- 투자금액은 계획금액이며 실제 집행액·현금유출액으로 표현하지 않는다.
- 종료일은 예정일일 수 있으므로 확정 준공일로 표현하지 않는다.
- 총사업비와 회사 부담액, 보조금과 대출, 연결과 별도 자기자본을 섞지 않는다.
- 핵심 Fact 일부가 없으면 `PARTIAL`, 질문의 핵심이 원문에 없으면 `UNANSWERABLE`, 파서 실패만 `FAILED`다.

## 6. 골든 후보 `GOLD-FACILITY-001`

승인 상태는 `C 검토대기`다. 대표문서·기대값은 대회 분석 워크북에 있으나, 원문 근거 위치까지 C가 확인한 뒤 고정 골든셋으로 승격한다.

| 항목 | 기대값 |
|---|---|
| 회사·접수번호 | SK하이닉스 `20240424800596` |
| 투자금액 | `5,296,200,000,000원` |
| 자기자본 | `53,503,752,397,611원` |
| 공시비율 | `9.9%` |
| 재계산 | `9.8987449715% → 9.9%` |
| 목적 | 선제적인 반도체 수요 대응을 위한 차세대 DRAM 생산능력 확장 |
| 시설투자 사건 상태 | 결정공시 기준 `DECIDED`; 실제 완료로 간주하지 않음 |
| 기대 답변 상태 | 대표 질문의 사실·계산·근거가 검증되면 `COMPLETED` |
| 승인 상태 | `C_REVIEW_PENDING` |

기대 근거 위치는 `투자내역 > 투자금액`, `자기자본`, `자기자본대비`, `투자목적`, `투자기간`, `이사회결의일`의 표 행과 산정 주석이다. 원문값·단위·정규화값을 한 Fact envelope에서 함께 검증한다.

허용 답변 요지:

> 공시된 투자금액은 5조 2,962억원이며, 목적은 차세대 DRAM 생산능력 확장입니다. 공시 자기자본 53조 5,037억여원을 기준으로 재계산하면 약 9.8987%, 표시값 9.9%로 공시비율과 일치합니다. 이는 계획금액 기준이며 실제 집행액을 뜻하지 않습니다.

치명적 오류:

- 자기자본 분모 오추출 또는 연결·별도 기준 혼용
- 목적 문구 왜곡
- 계획금액을 실제 집행액으로 표현
- 9.9%를 불일치로 판정
- 원문 단위·근거 누락
- 종료예정일을 실제 준공일로 표현
- 외부 최신 재무값으로 공시 당시 비율을 대체

## 7. B의 구현 순서

1. `exchange/신규시설투자등`과 정정본을 검색한다.
2. 핵심 8개 Fact의 표 행·주석을 `raw`로 추출한다.
3. 금액·통화·단위·날짜를 정규화하고 금액 속성을 별도로 저장한다.
4. 자기자본 기준시점·연결/별도·금액성격을 검증한다.
5. 정정공시에서 변경된 Fact만 적용해 기준시점 최신계획을 만든다.
6. 동일 공시 계산과 정기공시 연결 계산을 서로 다른 계산 그룹으로 구현한다.
7. `GOLD-FACILITY-001`의 Fact·근거·원계산값·표시값을 회귀검증한다.
8. 43건 전체 배치결과와 레이블·단위·주석 누락 유형을 반환한다.
