## 3. 생성 방식 검수

- 원문 사건명·주식종류·수량·금액·목적·날짜·상대방은 `DIRECT_RAW`다.
- 숫자·날짜·종목코드 형식은 `DIRECT_NORMALIZED`다.
- `event_type`, 목적코드, 기준시점 상태는 `DERIVED_CLASSIFICATION`이다.
- 평균가격·보유비율·진행률은 `DERIVED_CALCULATION`이다.
- 결정과 결과·신탁해지 관계는 `LINKED_RESOLVED`다.

## 6. 근거·상태·표현 정책

- 결정공시의 계획값과 결과공시의 실제값을 별도 Fact·문서 버전으로 보존한다.
- 보통주·우선주 등 주식종류별 표 행을 합계와 함께 검산한다.
- 신탁계약금액은 실제 자기주식 취득금액이 아니며, 해지 역시 자동 소각을 뜻하지 않는다.
- 처분대상자와 회사의 관계는 공시에 기재된 범위만 답한다.
- `event_type`은 문서 행위, `event_status`는 기준시점 사건상태, API 상태는 답변 완전성이다.
- 결정만 존재해도 “무엇을 결정했는가” 질문은 API `COMPLETED`가 가능하지만 “실제로 얼마나 샀는가” 질문은 결과공시가 없으면 `PARTIAL/UNANSWERABLE`이다.

승인 상태는 `C 검토대기`다. 이 후보는 취득결정의 **계획값**을 검증하며, 실제 취득결과와 2025년 소각결정은 별도 후속공시로 연결한다.

| 항목 | 기대값 |
|---|---|
| 회사·접수번호 | 삼성전자 `20241115000375` |
| 사건 | 직접 자기주식 취득결정 |
| 보통주 | `50,144,628주`, 예정금액 약 `2조 6,827억원` |
| 우선주 | `6,912,036주`, 예정금액 약 `3,173억원` |

| 목적 | 주주가치 제고 등 |
| 방법 | 유가증권시장을 통한 장내 매수 |

| 기대 답변 상태 | 계획 질문의 Fact·근거가 모두 있으면 사건 진행 중에도 `COMPLETED` 가능 |

정정 `20241118000171`은 위탁중개기관을 `삼성증권 등`에서 전체 기관명으로 확장한 것이므로 수량·금액을 변경하지 않는다.

기대 근거는 주식 종류별 예정수량·예정금액, 취득방법, 취득기간, 목적, 결정일, 위탁투자중개업자 표 행이다. 정정표에서는 중개기관 전후만 변경 근거로 사용한다.

치명적 오류:

- 예정수량·예정금액을 실제 취득결과로 표현
- 보통주와 우선주 수량·가격 혼합
- 정정되지 않은 수량·금액을 새 값으로 변경
- 직접취득과 신탁계약 혼동
- 자기주식 취득을 자동 소각으로 표현
- 자기주식 처분을 신주발행으로 표현
- 사건 `IN_PROGRESS`와 API `PARTIAL`을 같은 의미로 처리
- 원문 근거 없이 주가·EPS 효과를 단정

## 8. B의 구현 순서

1. 4개 주요 report name을 `event_type` 후보로 라우팅한다.
2. 주식종류별 표를 분리해 계획수량·금액과 실제 결과를 다른 필드로 추출한다.
3. 사건행위 코드와 기준시점 상태코드를 별도 생성한다.
4. 결정→결과, 신탁체결→해지 관계를 확정한다.
5. 주식종류·발행주식수·기준일 검증 후 비율과 진행률을 계산한다.
6. 처분대상·목적·소각 여부의 원문 근거를 연결한다.
7. C가 승인한 삼성전자 골든 후보에서 보통주·우선주와 중개기관 정정 범위를 회귀검증한다.
8. 결정만 있고 결과가 없는 문서를 별도 미완료군으로 반환한다.
