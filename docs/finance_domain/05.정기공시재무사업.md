## 2. 생성 방식 검수

- 보고서명·기준연도·기준월은 `SOURCE_METADATA`다.
- 재무제표·사업표의 계정명·값·단위·기간은 `DIRECT_RAW`다.
- 날짜·단위와 명확한 계정 동의어 매핑은 `DIRECT_NORMALIZED`다.
- 연결/별도, 당기/누적, 지배주주 귀속 등은 원문 축을 읽어 저장하며 단순 제목 추정은 금지한다.
- 이익률·증감률·부채비율은 `DERIVED_CALCULATION`이다.
- 정정 범위·최신 유효값은 `DERIVED_CLASSIFICATION`/`LINKED_RESOLVED`다.

## 5. 정정 Fact

| Fact ID | 의미 | 생성 방식 |
|---|---|---|
| `correction.scope.raw` | 정정 대상 장·절 원문 | `DIRECT_RAW` |
| `correction.scope.code` | 정정영역 코드 | `DERIVED_CLASSIFICATION` |
| `correction.reason.raw` | 정정사유 | `DIRECT_RAW` |
| `correction.original_submission_date` | 최초제출일 | `DIRECT_NORMALIZED` |

| `correction.changes[].after.raw` | 정정 후 원문값 | `DIRECT_RAW` |

`scope.code`는 `FINANCIAL_STATEMENT`, `FINANCIAL_NOTE`, `BUSINESS_INFORMATION`, `AUDIT_INFORMATION`, `GOVERNANCE`, `SHAREHOLDING`, `TYPOGRAPHICAL`, `UNKNOWN`을 사용한다. 정기공시가 정정됐다는 이유만으로 모든 재무값을 변경하지 않는다.

| 정정 범위 코드 | 뜻 | 변경 가능한 대표 Fact |
|---|---|---|
| `FINANCIAL_STATEMENT` | 재무상태표·손익계산서·현금흐름표 등 본표 정정 | 재무 본표 값 |
| `FINANCIAL_NOTE` | 재무제표 주석 정정 | 주석 세부값·회계정책 |
| `BUSINESS_INFORMATION` | 사업내용·임직원·R&D·수주 등 비재무 본문 정정 | 해당 사업 Fact만 |
| `AUDIT_INFORMATION` | 감사인·감사의견·감사보고서 관련 정정 | 감사 Fact만 |
| `GOVERNANCE` | 이사회·감사위원회·지배구조 정정 | 지배구조 Fact만 |
| `SHAREHOLDING` | 최대주주·주식총수·자기주식 등 정정 | 주식 Fact만 |
| `TYPOGRAPHICAL` | 의미값을 바꾸지 않는 오탈자·표현 정정 | 정규화값 동일 여부 검증 |
| `UNKNOWN` | 정정표만으로 영역을 판별하지 못함 | 자동 대체 금지 |

| 부채부담이 커? | 부채÷자본 | 같은 기준일의 회계상 자본 대비 부채 | 상환불능 확정 |
| 현금으로 차입금을 얼마나 상쇄해? | 차입금−현금 | 단순 참고 순차입 | 제한예금·리스·파생상품까지 반영한 순부채 |
| R&D 투입이 큰 편이야? | R&D÷매출 | 공시 정의상 연구개발비의 매출 대비 비중 | 연구성과·기술가치 |
| 배당성향은? | 배당총액÷해당 순이익 | 특정 정의의 이익 중 배당 비중 | 미래 배당 보장 |

## 7. 근거·상태·표현 정책

- 재무 Fact 근거에는 재무제표명, 연결/별도, 기간, 계정명, 열 머리글, 단위와 감사·검토 여부를 포함한다.
- 동일 계정명이 여러 표에 있으면 재무제표 종류와 기간축을 먼저 확인한다.
- 손실은 음수 부호를 보존하며 공란·대시를 0으로 바꾸지 않는다.
- 금융업의 영업수익을 일반 제조업 매출액과 같은 계정명으로 강제하지 않는다.
- 정기공시 정정은 `scope`에 포함된 Fact만 갱신한다.
- 기간·연결기준이 달라 계산할 수 없으면 확인된 직접값은 답하고 비교는 `PARTIAL`로 제한한다.
- 감사의견·핵심감사사항을 회사의 부도·분식 확정으로 표현하지 않는다.

## 8. 골든 후보

아래 사례는 `C 검토대기`다. 재무제표명·연결/별도·기간·표시단위와 정정표 범위를 원문에서 확인한 뒤 고정 골든셋으로 승격한다.

### `GOLD-PERIODIC-001`

삼성전자 사업보고서 `20240312000736`, 2023년 연결 재무제표를 사용한다.

| Fact | 기대값, 백만원 |
|---|---:|
| `financial.revenue` | 258,935,494 |
| `financial.operating_profit` | 6,566,976 |
| `financial.net_income` | 15,487,100 |
| `financial.total_assets` | 455,905,980 |
| `financial.total_liabilities` | 92,228,115 |
| `financial.total_equity` | 363,677,865 |

| 추가 검증 | 기대 |
|---|---|
| 보고서·기간 | 2023년 사업보고서, FY2023 |
| 회계기준 | 연결 |
| 원문단위 | 백만원 |
| 정규화단위 | KRW |
| 기대 API 상태 | 위 Fact와 근거가 모두 확인되면 `COMPLETED` |
| 승인 상태 | `C_REVIEW_PENDING` |

단위를 원으로 정규화하되 백만원 원문값을 보존한다. 연결값을 별도값으로 바꾸면 치명적 오류다.

### `GOLD-PERIODIC-CORR-001`

LG이노텍 `20240913000803`은 반기보고서의 임직원 관련 기재오류 정정이다. `scope=BUSINESS_INFORMATION`이며 재무제표 Fact 전체를 대체하지 않는다.

필수 검증은 정정 대상 장·절, 정정사유, 정정 전후 임직원 값, 최초제출일이다. 재무제표 수치를 새 버전으로 만들면 치명적 오류다. 승인 상태는 `C_REVIEW_PENDING`이다.

### 골든 후보 공통 치명적 오류

- 연결값과 별도값 혼용
- 백만원을 원으로 오인하거나 원문 단위 삭제
- 분기 누적값을 3개월 단일 분기값으로 표현
- 연결 전체 순이익과 지배주주 귀속 순이익 혼동
- 정정 플래그만 보고 모든 재무 Fact를 변경
- 손실 부호 제거
- 다른 기간·계정범위의 Fact로 비율 계산
- 원문 계정명·표 위치 없이 정규화 계정만 반환

## 9. B의 구현 순서

1. 문서의 보고기간·연결/별도·재무제표 종류·표시단위를 먼저 구조화한다.
2. 원문 계정명과 값을 `raw`로 저장하고 표준계정 매핑을 별도 반환한다.
3. 누적/당기·지배주주 귀속·시점/기간 Fact 검증기를 적용한다.
4. 검증된 동일 기준 Fact만 비교·계산한다.
5. 정정표의 scope와 changed Fact만 최신값에 반영한다.
6. C가 승인한 삼성전자 골든 후보 수치와 LG이노텍 정정 범위를 회귀검증한다.
7. 연차·반기·분기별 파싱 성공률과 계정 미매핑 목록을 반환한다.
8. 외부 OpenDART를 평가 답변 경로에 호출하지 않고 대회 원문만 근거로 사용한다.
