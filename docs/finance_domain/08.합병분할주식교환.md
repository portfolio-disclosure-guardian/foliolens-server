# 공시 분석유형 08: 합병·분할·주식교환

> 공통 적용 규격: [공시 분석유형 00: 공통 Fact·근거·계산·골든 규격](./공시_분석유형_00_공통규격.md)

## 1. 유형의 범위와 데이터 현황

법인의 구조나 권리관계가 바뀌는 합병, 회사분할, 분할합병, 주식교환·이전을 다룬다. 제공 데이터에는 합병 24건, 주식교환·이전 12건, 회사분할 12건, 분할합병 8건이 있으며 정정공시 비중이 높다.

유형 09의 자산·영업·지분거래와 달리 이 유형은 존속·소멸 법인, 분할신설법인, 완전자회사화 등 **법적 조직구조 변화**가 핵심이다.

합계 56건은 전체 4,204건의 1.33%, `major` 598건의 9.36%이며 정정표시는 29건, 51.79%다. 세부적으로 합병 24건(정정 9), 분할 12건(정정 7), 분할합병 8건(정정 7), 주식교환·이전 12건(정정 6)이다.

## 2. 지원 질문

- 어떤 회사가 존속하고 어떤 회사가 소멸하는가?
- 합병·분할·교환의 목적과 방식은 무엇인가?
- 합병비율·분할비율·교환비율은 얼마이며 공시 계산과 맞는가?
- 기존 주주가 받을 주식 수는 어떻게 정해지는가?
- 신주 수와 예상 지분구조는 어떻게 바뀌는가?
- 주주총회, 주식매수청구, 채권자보호, 효력발생 일정은 언제인가?
- 정정으로 비율·일정·조건이 무엇이 바뀌었는가?

## 3. 용어 사전

| 용어 | 뜻 | 주의사항 |
|---|---|---|
| 존속회사 | 합병 후 법인격이 남는 회사 | 사업 브랜드 존속 여부와 다를 수 있다. |
| 소멸회사 | 합병 효력 발생으로 법인격이 없어지는 회사 | 청산과 같은 절차라고 단정하지 않는다. |
| 인적분할 | 기존 주주가 분할회사와 신설회사 주식을 비례해 보유하는 분할 | 실제 배정구조는 공시 비율을 확인한다. |
| 물적분할 | 분할회사가 신설회사 주식을 보유하는 분할 | 기존 주주가 신설회사 주식을 직접 받는다고 보지 않는다. |
| 분할합병 | 일부 사업을 분할해 다른 회사와 합병하는 거래 | 분할과 합병의 대상·비율을 각각 추출한다. |
| 주식교환 | 한 회사가 다른 회사 주주에게 자기주식을 주고 완전자회사화하는 절차 | 현금대가가 함께 있을 수 있다. |
| 주식이전 | 기존 회사 주주가 신설 지주회사 등의 주식을 받아 완전자회사 구조를 만드는 절차 | 교환과 법적 구조가 다르다. |
| 주식매수청구권 | 반대주주가 법정 절차에 따라 회사에 주식매수를 요구하는 권리 | 청구가격과 실제 지급액은 다를 수 있다. |
| 단주 | 비율 계산 결과 1주 미만으로 남는 부분 | 현금 정산 방식은 원문을 따른다. |
| 흡수합병 | 한 회사가 존속하고 다른 회사의 권리·의무를 승계하는 합병 | 존속·소멸회사를 역할 Fact로 구분한다. |
| 신설합병 | 기존 회사들이 소멸하고 새 회사를 만드는 합병 | 단순히 흡수합병의 반대 코드로 추정하지 않는다. |
| 완전모회사 | 주식교환·이전 후 완전자회사의 발행주식을 전부 보유하는 회사 | 단순 최대주주와 다르다. |
| 완전자회사 | 발행주식 전부가 완전모회사에 귀속되는 회사 | 거래 완료 전에는 예정 상태다. |
| VWAP | `Volume-Weighted Average Price`, 거래량가중평균가격 | 가치산정 기준 중 하나이며 적정가치와 동일하지 않다. |
| 합병가액·교환가액 | 비율 계산에 사용하는 회사별 주당 평가액 | 실제 시장가격이나 미래 적정가격으로 단정하지 않는다. |
| 자산가치 | 조정 순자산 등을 기초로 계산한 주당가치 | 산식·기준일을 함께 보존한다. |
| 수익가치 | 미래 수익력 등을 반영해 평가한 주당가치 | 예측가정과 평가방법이 필요하다. |
| 본질가치 | 자산가치와 수익가치 등을 가중해 산정한 가치 | 공시가 사용한 가중치와 산식을 따른다. |
| 외부평가 | 외부평가기관이 거래비율·가치의 적정성 등을 검토한 절차 | 적정 의견이 거래 성공이나 주가상승을 보장하지 않는다. |
| 채권자 이의제출 | 합병·분할 과정에서 채권자가 이의를 제기할 수 있는 보호절차 | 거래 취소와 동일한 의미가 아니다. |
| 선행조건 | 거래 종결 전에 충족돼야 하는 승인·의무·조건 | 조건이 있다는 사실과 충족 여부를 분리한다. |
| MAE | `Material Adverse Effect`, 중대한 부정적 영향 | 공시 계약이 정의한 범위만 적용한다. |
| 소규모 절차 | 일정 요건에서 특정 회사의 주주총회 승인을 이사회 승인으로 대체하는 절차 | 모든 주주권리 소멸을 뜻하지 않는다. |
| 간이 절차 | 높은 지분보유 등 법정 요건에서 절차를 간소화하는 방식 | 소규모 절차와 같은 것으로 합치지 않는다. |

## 4. 생성 방식과 원문 분리 원칙

| 생성 방식 | 적용 예 | 검수 결과 |
|---|---|---|
| `DIRECT` | 회사명, 목적, 원문 비율, 일정, 매수청구가격 | 원문에 독립된 값이 있으면 그대로 저장한다. |
| `DIRECT_NORMALIZED` | `흡수합병`→`ABSORPTION_MERGER`, 날짜 ISO화, 금액 원화 | 반드시 `.raw`와 `.normalized/code`를 분리한다. |
| `DERIVED` | 합병신주 수 검산, 일정 변경일수 | 입력과 공식을 기록한다. |
| `LINKED` | 합병결정과 합병완료, 최초와 정정공시 연결 | 접수번호와 관계유형을 남긴다. |

이 절의 `DIRECT`, `NORMALIZED`, `CLASSIFIED`, `DERIVED`, `LINKED`는 설명용 축약어다. 실제 구현 메타데이터에는 공통 규격의 `DIRECT_RAW`, `TEXT_EXTRACTED`, `DIRECT_NORMALIZED`, `DERIVED_CLASSIFICATION`, `DERIVED_CALCULATION`, `LINKED_RESOLVED`를 기록한다. `CANDIDATE_LINK`는 Fact 생성 방식이 아니라 문서 관계의 미확정 상태이므로 최신값 병합에 사용하지 않는다.

`reorganization.method`가 원문에 `흡수합병`이라고 기재되어 있으면 원문은 `DIRECT`; 내부 코드만 `DIRECT_NORMALIZED`다. 공시가 제시한 합병비율은 `DIRECT`이며 백엔드가 다시 계산한 비율은 별도 `DERIVED`다.

## 5. Fact 사전

표의 Fact ID는 의미 단위 `factKey`다. `.raw`, `.normalized` 표기는 공통 Fact envelope의 원문값·정규화값 속성을 뜻한다. 접미사가 생략된 숫자·날짜·코드 Fact도 `rawValue`와 근거를 함께 보존하고, 계산값은 직접값과 다른 생성 방식으로 표시한다.

주주권리·거래조건은 회사별 값과 조건의 존재·충족상태를 분리한다.

`condition_type` 코드는 `SHAREHOLDER_APPROVAL`(주주승인), `REGULATORY_APPROVAL`(관계당국 승인), `APPRAISAL_LIMIT`(매수청구 한도), `REPRESENTATION_ACCURACY`(진술·보장 정확성), `COVENANT_COMPLIANCE`(계약상 의무 이행), `CLOSING_DEADLINE`(종결기한), `MUTUAL_AGREEMENT`(당사자 합의), `MAE_ABSENCE`(중대한 부정적 영향 부재), `OTHER`, `UNKNOWN`으로 사용한다.

### 5.5 정정 Fact

`correction.date`, `correction.reason`, `correction.original_disclosure_date`, `correction.scope[]`, `correction.changes[].fact_id/before/after`를 사용한다. 비율, 참여회사, 대가, 주주총회일, 효력발생일, 신주 수 변경을 각각 구조화하며 정정문 전체를 최신값으로 덮어쓰지 않는다.

### 6.1 계산을 만든 이유와 질문별 해석 한계

| 대응 질문 | 적용 계산 | 왜 계산하는가 | 말할 수 있는 것 | 말하면 안 되는 것 |
|---|---|---|---|---|
| 합병비율이 맞아? | `MERGER_RATIO_CHECK` | 공시된 양사 주당 합병가액과 표시비율의 산술 일치 확인 | 동일 기준 입력에서 재계산값과 공시값의 차이 | 비율의 경제적 공정성 확정 |
| 합병으로 얼마나 희석돼? | `EXISTING_HOLDER_DILUTION` | 신주가 거래 후 주식 수에서 차지하는 기계적 비중 확인 | 기존 주주의 상대 지분 감소 가능 규모 | 같은 비율의 주가 하락 |
| 분할비율이 맞아? | `DIVISION_RATIO_CHECK` | 거래마다 다른 공시 산식을 그대로 재현 | 공시 산식과 표시값 일치 여부 | 모든 분할의 보편적 순자산 공식 |
| 인적분할 비율 합계가 맞아? | `DIVISION_RATIO_SUM_CHECK` | 존속·신설비율이 전체 1을 구성하는지 확인 | 표시 비율 합계 | 분할 후 기업가치 증가 |
| 분할합병 최종 배정비율이 맞아? | `DIVISION_MERGER_ALLOCATION` | 공시가 분할비율과 합병비율의 곱을 사용했는지 검증 | 해당 공시 산식의 일치 여부 | 모든 분할합병에 같은 식 적용 |
| 자산·부채가 얼마나 넘어가? | 이전 자산·부채·순자산 비율 | 회사 전체 재무규모 대비 이전대상 규모 표현 | 동일 기준에서의 상대적 규모 | 거래 후 실적·가치 확정 |
| 매수청구가 많으면 취소돼? | `APPRAISAL_CAP_USAGE` | 청구액과 계약상 해제 한도의 관계 확인 | 한도 대비 청구규모와 해제권 조건 | 한도 초과 시 자동 취소 단정 |
| 일정이 얼마나 밀렸어? | `SCHEDULE_CHANGE_DAYS` | 같은 일정 항목의 정정 전후 차이 확인 | 연장·단축일수 | 지연 원인이나 거래 실패 단정 |

### 6.2 계산 불가·중단 조건

- 비율의 기준회사와 상대회사가 불명확하면 역수를 임의 선택하지 않는다.
- 보통주·우선주 등 주식종류가 다르면 한 비율로 합치지 않는다.
- 현금대가만 지급하고 신주를 발행하지 않으면 희석률을 계산하지 않는다.
- 자기주식 교부는 신주 발행과 분리한다.
- 분할비율 산식이 원문에 없거나 입력 정의가 다르면 순자산비율을 임의 대체식으로 사용하지 않는다.
- 예정 신주와 실제 발행 신주를 같은 수량으로 취급하지 않는다.
- 주식매수청구 예정가격·예상수량을 실제 지급액으로 표현하지 않는다.
- 연결·별도, 기준일, 통화가 다른 재무값은 직접 계산하지 않는다.

## 7. 상태·표현 정책

- `DECIDED`: 이사회 결정만 확인.
- `APPROVED`: 필요한 주주총회 승인 확인.
- `IN_PROGRESS`: 조건 충족·절차 진행 중.
- `COMPLETED`: 효력발생·등기·완료 공시가 확인됨.
- `CANCELLED`: 철회·부결·조건 불충족이 원문으로 확인됨.

상태는 한 열로 합치지 않는다.

| 상태축 | 코드 예 | 의미 |
|---|---|---|
| 의사결정 상태 | `DECIDED`, `CORRECTED`, `WITHDRAWN`, `UNKNOWN` | 이사회 결정 자체의 상태 |
| 주주승인 상태 | `NOT_REQUIRED`, `PENDING`, `APPROVED`, `REJECTED`, `UNKNOWN` | 주주총회 승인 절차 상태 |
| 규제승인 상태 | `NOT_REQUIRED`, `PENDING`, `APPROVED`, `CONDITIONAL`, `REJECTED`, `UNKNOWN` | 관계당국 승인 상태 |
| 거래 진행상태 | `SCHEDULED`, `IN_PROGRESS`, `EFFECTIVE`, `COMPLETED`, `TERMINATED`, `FAILED`, `UNKNOWN` | 사건 자체의 최신 진행상태 |
| API 답변상태 | `COMPLETED`, `PARTIAL`, `UNANSWERABLE`, `FAILED` | 질문에 답할 데이터·시스템 상태 |

거래가 해제되어 `transaction_status=TERMINATED`여도 해제 사실과 근거를 정상적으로 찾았다면 `answer_status=COMPLETED`다. 거래상태의 `FAILED`와 API 시스템 실패의 `FAILED`도 서로 다른 필드에 저장한다.

### 7.1 원문 근거 최소 조건

핵심 Fact에는 접수번호, 문서유형, 절·표 제목, 행·열명 또는 문장 위치, 원문 텍스트, 원문값·단위, 정규화값·단위, 기준일·기간·회계기준을 연결한다. 비율에는 반드시 `기준회사 1 : 상대회사 R` 방향을 보존하고, 정정값에는 정정 전·후와 변경 Fact ID를 함께 남긴다.

### 7.2 답변 상태 판정

| API 상태 | 판정 기준 |
|---|---|
| `COMPLETED` | 질문에 필요한 거래구조·당사자 역할·비율 또는 상태·근거가 모두 확인됨 |
| `PARTIAL` | 핵심 일부는 확인했지만 비율 방향, 최신상태, 대가, 조건 중 질문에 필요한 항목이 빠짐 |
| `UNANSWERABLE` | 제공 공시에 질문의 핵심정보가 없거나 기준시점 내 관련문서를 확정할 수 없음 |
| `FAILED` | 검색·파싱·정규화·계산 시스템이 실패함 |

“합병이 확정됐다”는 완료 근거가 있을 때만 사용한다. 합병비율이 유리·불리하다거나 주가가 오를 것이라고 단정하지 않는다.

## 8. 골든 후보

아래 사례는 `C 검토대기`다. 특히 비율 방향, 존속·소멸회사 역할, 정정 대상 첨부의 실제 변경 범위를 원문에서 승인해야 한다.

### 8.1 공통 치명적 오류 목록

- 존속회사와 소멸회사를 반대로 답함.
- 인적분할과 물적분할을 혼동함.
- 물적분할에서 기존 주주가 신설회사 주식을 직접 받는다고 답함.
- 분할비율·합병비율·최종 배정비율을 같은 값으로 처리함.
- 비율 방향을 확인하지 않고 역수로 계산함.
- 현금대가 주식교환에서 신주 희석률을 계산함.
- 예정 신주를 실제 발행 완료 주식으로 답함.
- 외부평가의 적정 의견을 거래 성공·주가 상승 보장으로 해석함.
- 주식매수청구 예정가격을 최종 확정가격으로 표현함.
- 매수청구 한도 초과를 자동 계약해제로 단정함.
- 소규모·간이 절차를 모든 주주권리 소멸로 해석함.
- 최초공시만 사용하고 최신 정정·해제공시를 누락함.
- 거래상태 `TERMINATED`를 API 답변상태 `FAILED`로 처리함.
- 근거 없이 호재·악재, 적정기업가치, 주가방향을 단정함.

## 9. B의 구현 순서

1. 제목과 서식으로 사건 유형·행위를 분류한다.
2. 참여회사 표를 파싱해 회사마다 역할을 부여한다.
3. 비율은 원문 문자열·방향·정밀도를 먼저 저장하고 표준 방향 값을 별도로 만든다.
4. 신주·대가·분할대상 사업·일정·주주권리 표를 사건별로 추출한다.
5. 최초·정정·승인·완료공시를 연결해 사건 상태를 갱신한다.
6. 동일 기준 입력만 계산 엔진에 전달하고 공시 비율과 재계산값을 병렬 보존한다.
7. C가 승인한 두 골든 후보로 역할·비율방향·첨부정정·상태 전이를 회귀검증한다.
8. 네 골든 후보의 원문 위치와 기대값이 승인되면 회귀테스트에 고정하고, 정정·해제 공시가 추가될 때 최신상태 회귀검사를 수행한다.
