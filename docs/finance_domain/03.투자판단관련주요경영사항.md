> 공통 적용 규격: [공시 분석유형 00: 공통 Fact·근거·계산·골든 규격](./공시_분석유형_00_공통규격.md)

300건은 전체 4,204건의 7.14%, `exchange` 1,469건의 20.42%이며 정정표시는 53건, 17.67%다. 같은 제목 안에 MOU·LOI·임상·허가·마일스톤·정부지원 등 서로 다른 사건이 들어가므로 문서 수보다 사건구조 분류가 중요하다.

## 1. 용어

| 용어 | 정의 | 처리 원칙 |

| MOU | Memorandum of Understanding, 업무협약·양해각서 | 법적 구속력과 확정계약 여부를 원문에서 확인 |

| 조건부대가 | 특정 성과 달성 시 지급되는 금액 | 최대금액과 실제 확정금액 분리 |
| 이행보증 | 계약상 의무 이행을 보증하는 약정 | 즉시 현금지출 또는 손실로 단정 금지 |

## 3. 생성 방식 검수

- 제목·주요내용·당사자·금액·날짜·조건 문장은 `DIRECT_RAW`다.
- 날짜·통화·숫자 형식만 `DIRECT_NORMALIZED`다.
- 사건유형·계약단계·마일스톤 상태·금액성격은 `DERIVED_CLASSIFICATION`이다.
- 현재 상태는 후속공시까지 연결한 분류, 문서 연결은 `LINKED_RESOLVED`다.
- 가능성 문구만 있는 마일스톤 금액을 `DIRECT_RAW` 확정금액으로 만들지 않는다.

## 4. Fact 사전

Fact는 의미 단위의 `factKey` 하나와 공통 envelope로 구현한다. 표의 `.raw`, `.raw_text`, `.value`, `.normalized_value`는 별도 factKey를 만들라는 뜻이 아니라 각각 `rawValue`와 `normalizedValue`를 구분해 설명한 경로다. 원문값·단위·근거를 보존하지 못한 정규화값은 `VERIFIED`로 올리지 않는다.

## 5. 계산과 해석

| 계산 | 공식 | 조건·금지 |
|---|---|---|
| 확정 마일스톤 비중 | 확정금액÷최대조건부금액×100 | 실제 달성·동일 통화일 때만; 성공확률 아님 |
| 정부보조금 비중 | 보조금÷총투자금액×100 | 같은 프로젝트·통화·금액기준이며 총투자액과 지원액의 포함관계가 원문에서 확인될 때 |
| 회사 순부담 참고액 | 총투자액−확정 보조금 | 총투자액이 보조금 차감 전 총사업비임이 확인될 때만; 대출은 빼지 않으며 실제 순현금유출 확정 아님 |
| 기간 | 종료일−시작일 | 계획기간임을 표시 |
| 정정금액 변화 | 정정 후−정정 전 | 같은 금액성격일 때 |
| 임상 등록률 | 실제 등록인원÷목표인원×100 | 같은 프로토콜·기준일일 때만; 임상 성공률 아님 |
| 옵션 대상비율 | 옵션 대상주식÷동일 기준 발행주식×100 | 잠재 지배권 변화 범위; 실제 행사·지배권 변경 아님 |

### 계산을 만든 이유와 질문 대응

| 대응 질문 | 계산 | 말할 수 있는 범위 | 말하면 안 되는 내용 |
|---|---|---|---|
| 최대 계약금 중 이번 마일스톤은 어느 정도야? | 확정 마일스톤÷최대조건부금액 | 동일 계약 내 두 금액의 단순 구성비 | 계약 진행률·사업 성공확률 |
| 정부지원이 투자비의 얼마야? | 확정 보조금÷총투자액 | 동일 프로젝트에서 무상지원의 상대적 크기 | 회사의 실제 순부담 확정 |
| 대출까지 빼면 회사 부담이 줄어? | 계산하지 않음 | 대출은 조달원천으로 별도 표시 | 상환의무 있는 대출을 비용 절감으로 처리 |
| 임상 대상자 모집은 얼마나 됐어? | 등록인원÷목표인원 | 해당 기준일 모집 비율 | 임상 결과 성공 가능성 |
| 콜옵션이 지분에 미치는 최대 범위는? | 옵션주식÷발행주식 | 전량 행사 가정의 대상 비중 | 실제 최대주주 변경 확정 |

마일스톤 구성비는 상태가 최소 `ACHIEVED`이고, 분자·분모의 계약범위·회사 귀속범위·통화가 같으며 최대대가에 해당 마일스톤이 포함된다는 근거가 있을 때만 계산한다.

## 6. 근거·상태·표현 정책

- MOU·LOI는 구속력 판단에 사용한 전체 문장을 evidence로 보존한다.
- 마일스톤은 `달성`, `청구`, `수령 예정`, `실제 입금`, `수익 인식`을 판정한 문장을 각각 연결한다.
- 임상은 신청·승인·개시·결과·허가 단계를 혼동하지 않는다.
- 최대 계약대가, 선급금, 조건부 마일스톤, 로열티, 실제 수령액을 하나의 대표금액으로 합치지 않는다.
- 정부 보조금, 대출, 출자, 보증한도는 상환의무와 현금흐름 성격이 다르므로 별도 Fact로 유지한다.
- 사건 상태와 API 답변 상태를 분리한다. 예를 들어 MOU 사건이 `MOU_SIGNED`여도 MOU 내용 질문은 API `COMPLETED`가 가능하다.
- 공시에서 확인할 수 없는 실제 수령·상업화·지배권 변경을 물으면 확인된 단계까지만 답하고 `PARTIAL` 또는 `UNANSWERABLE`로 처리한다.

## 8. B의 구현 순서

1. 300건을 제목·본문 키워드로 사건 후보군까지 라우팅하되 검색에서 제외하지 않는다.
2. 고정 표와 주요내용 문단을 함께 evidence로 복원한다.
3. 제목·대상·당사자·금액·날짜·조건을 `raw`로 우선 추출한다.
4. 계약단계·금액성격·마일스톤 상태는 규칙 결과와 근거문장을 함께 반환한다.
5. MOU·LOI 구속력과 마일스톤의 달성·청구·수령예정·입금·수익인식을 각각 판정하고 근거문장을 반환한다.
6. 정정·후속공시를 연결해 기준시점 상태를 산출한다.
7. 임상·기술이전·옵션 Fact의 자유서술 추출값과 원문 span을 함께 반환한다.
8. C가 승인한 세 골든 후보에서 보조금·대출·보증·출자, MOU·본계약, 청구·수령 상태를 각각 회귀검증한다.
9. 자유서술 미추출 사례를 의미군으로 묶어 C에게 반환한다.
