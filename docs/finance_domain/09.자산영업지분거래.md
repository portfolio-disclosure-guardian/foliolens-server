# 공시 분석유형 09: 자산·영업·지분거래

> 공통 적용 규격: [공시 분석유형 00: 공통 Fact·근거·계산·골든 규격](./공시_분석유형_00_공통규격.md)

## 1. 유형의 범위와 데이터 현황

회사가 유형·무형자산, 사업부문 또는 다른 회사 지분을 취득·처분하는 거래를 다룬다. 제공 데이터에는 타법인 주식·출자증권 취득 7건, 처분 1건, 유형자산 처분 3건, 유형자산 취득 2건, 영업양수 2건이 있다. 정정공시를 포함하면 조건·일정 변화도 함께 추적해야 한다.

유형 08과의 구분 기준은 법적 조직재편 여부다. 단순 지분취득으로 지배력을 얻더라도 합병·분할·주식교환 절차가 아니라면 유형 09다.

합계 15건은 전체 4,204건의 0.36%, `major` 598건의 2.51%이며 정정표시는 10건, 66.67%다. 타법인 주식 양수 7건, 유형자산 양도 3건, 영업양수 2건, 유형자산 양수 2건, 타법인 주식 양도 1건이다. 문서 수가 적어도 금액성격·단계별 지급·조건부대가·종결상태가 복잡하므로 Fact를 축소하지 않는다.

## 2. 지원 질문

- 무엇을 누구에게서 얼마에 취득·처분하는가?

- 회사 총자산·자기자본·매출 대비 거래 규모는 얼마인가?

## 3. 용어 사전

| 용어 | 뜻 | 주의사항 |
|---|---|---|
| 영업양수·양도 | 사업 수행에 필요한 자산·부채·인력·계약 등을 묶어 이전 | 단일 자산매매와 구분한다. |
| 지분취득 | 주식·출자지분을 매수·출자해 보유비율을 높이는 행위 | 경영권 취득 여부는 원문 목적·계약을 확인한다. |
| 장부가액 | 회계장부에 인식된 자산·지분의 금액 | 시장가치·공정가치와 다를 수 있다. |
| 조건부대가(earn-out) | 거래 후 성과·허가 등 조건을 달성하면 추가 지급하는 금액 | 최대금액이 실제 지급액을 뜻하지 않는다. |
| 클로징(closing) | 선행조건 충족 후 소유권·대금이 실제 이전되는 거래 종결 | 계약체결일과 다를 수 있다. |
| 암시 지분가치 | 일부 지분 거래금액을 100%로 단순 환산한 값 | 공정가치나 적정기업가치가 아니다. |
| Acquisition | 영업·자산·주식을 취득하는 것 | 양수·인수와 같은 방향으로 정규화하되 원문 보존 |
| Disposal / Divestiture | 영업·자산·주식을 처분하는 것 | 양도·매각과 같은 방향으로 정규화하되 원문 보존 |
| Business Transfer | 특정 사업의 자산·계약·인력 등을 묶어 이전하는 거래 | 단일 유형자산 거래와 구분 |
| APA | `Asset Purchase Agreement`, 자산양수도계약 | SPA와 구분 |
| SPA | `Share Purchase Agreement`, 주식매매계약 | 자산 자체가 아닌 법인 지분 거래 |
| Consideration | 현금·주식·채무인수 등을 포함할 수 있는 거래대가 | 현금만으로 한정하지 않음 |
| First/Second/Final Closing | 단계별 1차·2차·최종 거래종결 | 각 단계의 예정·실제 상태 분리 |
| Contingent Consideration | 조건에 따라 지급 여부·금액이 달라지는 조건부대가 | 확정대가로 합치지 않음 |
| Purchase Price Adjustment | 순차입금·운전자본 등에 따른 거래가격 사후조정 | 원문 산식 없이 임의 계산 금지 |
| Enterprise Value | 사업 전체의 영업가치를 기준으로 본 가치 | 지분가치와 구분 |
| Equity Value | 주주에게 귀속되는 지분가치 | 기업가치와 부채·현금 조정관계 확인 |
| Controlling Interest | 회사 활동을 지배할 수 있는 지분·권리 | 지분율 50% 초과만으로 자동 확정하지 않음 |
| Conditions Precedent | 거래종결 전 충족해야 하는 선행조건 | 조건 존재와 충족을 분리 |
| MAE | `Material Adverse Effect`, 중대한 부정적 변화 | 계약이 정의한 범위에 한해 적용 |
| Gross Proceeds | 비용 차감 전 총처분대금 | 순유입액과 구분 |
| Net Proceeds | 거래비용·세금을 차감한 순처분대금 | 원문 비용이 없으면 계산하지 않음 |

## 4. 생성 방식 전수 기준

| 방식 | 의미 | 이 유형의 예 |
|---|---|---|
| `DIRECT` | 원문에 독립적으로 적힌 값 | 거래대상, 상대방, 목적, 원문금액 |
| `DIRECT_NORMALIZED` | 직접값을 단위·코드·날짜로 표준화 | `4,435억원`과 단위를 `443,500,000,000원`으로 변환 |
| `DERIVED` | Fact들로 계산 | 거래금액/총자산, 평균 주당가격 |
| `LINKED` | 다른 공시·정기보고서에서 연결 | 최신 총자산, 완료공시, 대상회사 재무값 |

`DIRECT_NORMALIZED`는 백엔드가 값을 새로 창작한다는 뜻이 아니다. 원문 `유형자산 처분결정`을 그대로 보존하면서 코드 `ASSET_DISPOSITION_DECISION`을 추가하는 처리다.

이 절과 Fact 표의 `DIRECT`, `DERIVED`, `LINKED`는 설명용 축약이다. 실제 생성 메타데이터에는 각각 공통 규격의 `DIRECT_RAW`, `DERIVED_CLASSIFICATION` 또는 `DERIVED_CALCULATION`, `LINKED_RESOLVED`를 기록한다. 서술형 목적·배경·조건에서 구절을 뽑은 경우에는 `TEXT_EXTRACTED`를 사용한다. 원문 표에 있는 값을 단순히 읽은 경우와 그 값을 원 단위·ISO 날짜·표준코드로 바꾼 경우를 하나의 생성 방식으로 합치지 않는다.

## 5. Fact 사전

표의 Fact ID는 의미 단위 `factKey`다. `.raw`, `.normalized`, `.code`는 동일 Fact envelope 안의 원문값·정규화값·분류값을 구분한 논리 경로다. 접미사가 없는 금액·날짜·수량도 원문값·원문단위·근거를 함께 저장하며, 외부 문서 연결값은 출처 접수번호를 추가한다.

### 5.10 정정·관련공시

`correction.date/reason/original_disclosure_date/changes[].fact_id/before/after`와 `transaction.related_disclosures[].receipt_no/relation_type`을 사용한다. 종결일 정정은 계약 취소와 다르며, 금액·지분·대상 변경을 각각 판정한다.

`correction.scope`는 변경영역을 나타내며 `TARGET`, `TRANSACTION_AMOUNT`, `AMOUNT_NATURE`, `PAYMENT_SCHEDULE`, `FX_RATE`, `OWNERSHIP`, `COUNTERPARTY`, `PURPOSE_EFFECT`, `VALUATION`, `FUNDING_SOURCE`, `CLOSING_DATE`, `REGISTRATION_DATE`, `CONDITIONS`, `OPTIONS`, `FTC_FILING`, `LINKED_TRANSACTION`, `TERMINATION`, `TRANSACTION_STATUS`, `OTHER`, `UNKNOWN`을 사용한다. 실제 변경값은 반드시 `changes[].fact_id`에 개별 Fact 단위로 기록한다.

### 5.11 서로 합치면 안 되는 상태축

| 상태축 | 코드와 의미 |
|---|---|
| 결정상태 | `DECIDED` 결정, `CORRECTED` 결정내용 정정, `WITHDRAWN` 철회, `UNKNOWN` 확인불가 |
| 지급상태 | `NOT_STARTED` 미지급, `PARTIALLY_PAID` 일부지급, `PAID` 지급완료, `REFUNDED` 환급, `UNKNOWN` 확인불가 |
| 종결상태 | `NOT_STARTED` 미착수, `CONDITIONS_PENDING` 선행조건 대기, `PARTIAL_CLOSING` 일부종결, `FINAL_CLOSING` 최종종결, `TERMINATED` 해제·중단, `EXPIRED` 기한만료, `UNKNOWN` 확인불가 |
| 소유권 이전상태 | `NONE` 미이전, `PARTIAL` 일부이전, `REALIZED` 이전완료, `REVERSED` 원상회복·반환, `UNKNOWN` 확인불가 |

예정일이 지났다는 이유만으로 `PAID`, `FINAL_CLOSING`, `REALIZED`를 부여하지 않는다. 하나의 거래가 `결정=DECIDED`, `지급=PARTIALLY_PAID`, `종결=CONDITIONS_PENDING`, `소유권=NONE`일 수 있다.

정기공시 연결 계산은 연결·별도 기준, 기준일, 통화가 일치할 때만 수행한다.

### 6.4 실행 가능한 계산 계약

각 계산에는 계산 ID, 대응 질문, 입력 Fact ID, 결과 Fact ID, 원단위·통화, 기준일·회계기준, 계산 가능·불가 조건, 고정밀 원결과, 표시 반올림, 공시값 허용오차, 허용·금지 해석을 기록한다. LLM은 숫자를 직접 계산하지 않는다.

| 계산 ID | 실제로 구하는 값 | 입력조건 | 결과 해석 한계 |
|---|---|---|---|
| `ASSET_TOTAL_ASSET_RATIO_CHECK` | 공시 거래금액이 공시 기준 총자산의 몇 %인지 | 같은 통화·기준일·연결/별도 | 거래의 상대규모이지 성공·실패 아님 |
| `AVERAGE_PRICE_PER_SHARE` | 전체 고정 주식대가의 단순 주당가격 | 조건부대가·비주식대가 제외 가능 | 실제 장내 체결단가 아님 |
| `OWNERSHIP_CHANGE_PP` | 지분율 자체가 몇 퍼센트포인트 변했는지 | 같은 주식종류·분모 기준 | 상대적 감소율과 다름 |
| `IMPLIED_100_PERCENT_EQUITY_VALUE` | 일부 지분가격을 100% 기준으로 단순 환산한 값 | 취득지분율을 0~1 소수로 입력, 고정대가 | 공정가치·적정기업가치 아님 |
| `PAYMENT_SUM_CHECK` | 계약금·중도금·잔금 합계와 총액의 일치 | 같은 통화·금액성격 | 지급완료 여부를 뜻하지 않음 |
| `EARNOUT_MAX_SHARE` | 최대 거래대가 중 성과조건부 최대금액 비중 | 확정대가와 최대 조건부대가의 정의 확인 | 지급확률 아님 |
| `SIMPLE_DISPOSAL_SPREAD` | 처분금액과 장부가액의 단순 차이 | 동일 기준 금액 | 회계상 처분이익 아님 |
| `ESTIMATED_DISPOSAL_GAIN` | 처분금액−장부가−직접비용−세금 | 모든 입력과 회계처리가 확인될 때만 | 최종 회계상 손익과 다를 수 있음 |
| `NET_PROCEEDS` | 총처분대금−직접비용−세금 | 비용·세금이 공시된 경우 | 회사 전체 현금 증가액 아님 |

공시 표시값은 원문 소수 자릿수를 보존하고, 재계산값은 충분한 정밀도로 저장한다. 공시가 소수 둘째 자리까지 표시한 경우 비교표시값은 원계산값을 소수 셋째 자리에서 반올림하되, 입력값 자체가 반올림됐으면 정확 불일치 판정을 하지 않는다.

### 6.5 계산·표현 불가 조건

- 외화금액이 “약 66.1억 달러”처럼 반올림되어 있으면 환산은 근사값으로만 제시한다.
- 영업현금흐름이 0 또는 음수이면 일반적인 부담비율로 해석하지 않는다.
- 거래금액에 주식 외 대가·조건부대가·비용이 섞여 있으면 평균 주당가격 계산을 중단하거나 적용범위를 명시한다.
- 거래 전후 지분율의 분모 기준일·주식종류가 다르면 변화 계산을 중단한다.
- 비용·세금이 없으면 순처분대금과 추정 처분이익을 계산하지 않는다.
- 지분율이 50%를 넘는다는 이유만으로 지배력 취득을 확정하지 않는다.
- 단계별 지급예정액 합계가 총액과 같아도 실제 지급완료로 판정하지 않는다.

### 6.6 원문 근거와 답변 상태

거래대상은 대상 표·설명, 거래금액은 값·단위·금액성격, 목적은 양수·양도 목적 원문, 상대방은 상대방 표, 일정은 답변에 사용한 결정·계약·종결·등기일, 지분율은 전후 주식수·비율·분모, 조건부대가는 성과조건·상한, 완료는 지급·등기·주식이전·종결 문구, 취소는 해제·철회·종료 사유, 외부평가는 기관·방법·의견을 최소 근거로 연결한다.

| API 상태 | 기준 |
|---|---|
| `COMPLETED` | 질문에 필요한 Fact·근거·계산조건·기준시점 상태가 모두 확인됨 |
| `PARTIAL` | 핵심 일부는 답할 수 있으나 완료 여부·조건부대가·분모 기준 등 질문 필수항목이 빠짐 |
| `UNANSWERABLE` | 제공 공시에서 핵심 Fact를 확인할 수 없음 |
| `FAILED` | 조회·파싱·정규화·계산 시스템 처리 실패 |

거래가 취소됐다는 정상 답변도 근거가 완전하면 `COMPLETED`다.

### 7.1 공통 치명적 오류

1. 양수와 양도를 반대로 분류.
2. 거래대상과 거래상대방을 혼동.
3. 예정금액을 실제 지급금액으로 표현.
4. 최대·추정·조건부대가를 확정금액으로 표현.
5. Earn-out 지급을 확정적으로 표현.
6. 반올림 외화금액으로 환율 오류를 단정.
7. 계약일·종결일·등기일을 동일하게 취급.
8. 정정 전 값을 최신 조건으로 답변.
9. 종료된 거래를 진행 중으로 답변.
10. 지분율 분모 기준일이 다른 값을 계산.
11. 지분율 50% 초과만으로 지배력 확정.
12. 외부평가 적정을 거래 성공·주가상승으로 해석.
13. 처분금액을 처분이익으로 답변.
14. 비용·세금 없이 순처분대금 계산.
15. 자산양수도와 영업양수도 혼동.
16. 주주총회·주식매수청구권 적용 여부를 근거 없이 판단.
17. 거래를 근거로 주가·수익성을 예측하거나 매수·매도 추천 제공.

## 8. B의 구현 순서

1. 서식으로 자산·영업·지분과 취득·처분을 분류한다.
2. 대상·상대방·목적·금액·일정을 원문 근거 위치와 함께 추출한다.
3. 원문 금액·외화·VAT·성격을 보존하고 별도 정규화값을 만든다.
4. 지분거래·영업거래의 선택 Fact와 단계별 지급·조건부대가를 파싱한다.
5. 최초·정정·완료공시 및 필요한 정기공시를 연결한다.
6. 같은 기준의 입력만 결정적 계산기에 전달한다.
7. C가 승인한 골든 후보에서 지급합계, 상태, 처분차액 표현 제한을 검증한다.
