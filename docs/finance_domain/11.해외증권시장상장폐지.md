# 공시 분석유형 11: 해외증권시장 상장·상장폐지

> 공통 적용 규격: [공시 분석유형 00: 공통 Fact·근거·계산·골든 규격](./공시_분석유형_00_공통규격.md)

## 1. 유형의 범위와 데이터 현황

해외 거래소에 주식·예탁증권 등을 상장하기로 결정하거나 실제 상장한 사건, 상장폐지를 결정하거나 완료한 사건을 다룬다. 제공 데이터에는 해외증권시장 상장결정 1건, 상장 1건, 상장폐지결정 4건, 상장폐지 4건이 있다.

`생애주기`처럼 추상적인 이름 대신 사용자가 실제로 묻는 사건을 그대로 드러내는 `해외증권시장 상장·상장폐지`를 유형명으로 사용한다.

관련 10건은 전체 4,204건의 약 0.24%, `major` 598건의 약 1.67%다. 이 유형에는 정정표시 문서가 없지만 결정→완료 연결이 필수다. 대표적으로 카카오 싱가포르 GDR 폐지, SK텔레콤 런던 DR 폐지와 뉴욕 유지, 현대자동차 런던·룩셈부르크 복수 DR 폐지, 삼성전자 룩셈부르크→런던 DR 이전상장이 포함된다.

## 2. 지원 질문

- 어느 해외 거래소에 어떤 증권을 상장·폐지하는가?
- 결정공시와 실제 완료공시는 각각 언제인가?
- 신규발행, 기존주식, 구주매출, 예탁증권 중 어떤 방식인가?
- 해외상장 주식·예탁증권 수와 국내 발행주식 대비 비율은 얼마인가?
- 상장폐지 후에도 국내시장 거래는 가능한가?
- 정정 또는 후속공시로 일정·수량·거래소가 바뀌었는가?

예전 최종본에서 합의한 질문 18개를 다음과 같이 유지한다.

| 질문 ID | 질문 예시 | 필요한 Fact·판정 |
|---|---|---|
| `OSL-Q01` | 어느 해외 거래소에 상장하기로 했어? | 사건행위, 거래소, 결정일 |
| `OSL-Q02` | 실제 상장이 완료됐어? | 결정·완료공시 관계, 실제 상장일 |
| `OSL-Q03` | 어느 거래소에서 상장폐지했어? | 거래소별 사건상태, 실제 매매종료일 |
| `OSL-Q04` | 왜 해외상장을 폐지했어? | 폐지사유 원문 |
| `OSL-Q05` | 언제 결정됐고 언제 완료됐어? | 결정일·예정일·실제일 |
| `OSL-Q06` | 상장된 증권은 원주야, DR이야? | 증권유형 원문·코드 |
| `OSL-Q07` | 어떤 주식을 기초로 한 DR이야? | 원주 종류·권리조건 |
| `OSL-Q08` | 원주와 DR의 교환비율은? | 비율 원문과 방향, 원주·DR 단위 |
| `OSL-Q09` | 공시 DR 수량이 교환비율과 맞아? | 원주 수, DR 수, 환산비율 |
| `OSL-Q10` | 신규 자금조달을 위한 상장이야? | 신주발행·구주매출·모집·자금조달 문구 |
| `OSL-Q11` | 기존 주주 지분이 희석돼? | 신주 여부·신주 수·증자 전 주식 수 |

| `OSL-Q13` | 폐지 후 DR 보유자는 어떻게 돼? | 원주전환·대체시장·매각·현금지급 조치 |

| `OSL-Q17` | 예정일보다 실제 상장이 늦었어? | 예정일·실제일, 일정차이 |
| `OSL-Q18` | 해외상장폐지면 국내에서도 폐지돼? | 대상 해외시장과 국내 상장상태 분리 |

## 3. 용어 사전

| 용어·코드 | 뜻 | 주의사항 |
|---|---|---|
| 해외증권시장 | 대한민국 밖의 증권거래소·시장 | 거래소명과 소재국가를 별도 저장한다. |
| DR(Depositary Receipt) | 원주를 예탁기관에 맡기고 해외에서 거래하도록 발행한 예탁증권 | DR 수와 원주 수의 환산비율을 확인한다. |
| ADR | 미국시장에서 거래되는 미국예탁증권 | 모든 DR이 ADR은 아니다. |
| GDR | 여러 국제시장에서 유통될 수 있는 글로벌예탁증권 | 거래소·프로그램 조건 확인이 필요하다. |
| 구주매출 | 회사가 신주를 발행하지 않고 기존 주주 보유주식을 투자자에게 매각 | 회사로 자금이 유입되는 신주발행과 다르다. |
| `LONDON_STOCK_EXCHANGE` | 런던증권거래소를 나타내는 내부 표준 코드 | 원문 거래소명을 대체하지 않고 검색용으로 함께 저장한다. |
| 제2우선주 | 회사가 정관·발행조건에 따라 붙인 두 번째 종류 또는 시리즈의 우선주 | 경제적 우선순위가 항상 “2순위”라는 뜻은 아니다. |
| 원주 | DR의 기초가 되는 실제 주식 | DR 1개와 원주 1주의 비율이 다를 수 있다. |
| 예탁기관 | 원주를 기초로 DR을 발행·관리하는 금융기관 | 원주전환·잔여 DR 처리 역할은 공시 조건 확인 |
| 참가적 우선주 | 우선배당 후 일정 조건에서 추가 배당에 참여할 수 있는 우선주 | 회사별 정관·발행조건 필요 |
| 비참가적 우선주 | 정해진 우선배당 외 추가 배당에 참여하지 않는 우선주 | “우선주”라는 명칭만으로 자동 판정 금지 |
| 누적적 우선주 | 미지급 우선배당이 다음 기간으로 누적되는 우선주 | 실제 누적조건 확인 |
| 비누적적 우선주 | 미지급 우선배당이 다음 기간으로 누적되지 않는 우선주 | 제2우선주 여부와 별개 |

## 4. 생성 방식 전수검수

| 대상 | 올바른 생성 방식 | 이유 |
|---|---|---|
| 공시 제목의 `해외증권시장상장결정` | `DIRECT` | 제목에 직접 존재한다. |
| 이를 `LISTING_DECISION`으로 바꾼 값 | `DIRECT_NORMALIZED` | 검색용 코드로 표준화했다. |
| 표에 독립 기재된 거래소명 | `DIRECT` | 별도 해석 없이 직접 읽는다. |
| 거래소 원문을 `LONDON_STOCK_EXCHANGE`로 매핑 | `DIRECT_NORMALIZED` | 원문과 표준 코드가 분리된다. |
| `신규발행 상장` 등 명시된 방식 | 원문 `DIRECT`, 코드 `DIRECT_NORMALIZED` | 원문 라벨이 명확한 경우다. |
| 여러 문장으로 신규발행·구주·DR 구조를 판단 | `DERIVED_CLASSIFICATION` | 단일 원문값이 아니므로 판단근거를 기록한다. |
| 결정공시와 완료공시 관계 | `LINKED` | 두 접수번호 사이의 사건 관계다. |

이전 명세에서 거래소명을 통째로 `DIRECT_NORMALIZED`라고 적은 것은 부정확하다. `market_name.raw`는 `DIRECT`, `market_code`만 `DIRECT_NORMALIZED`다.

이 절과 Fact 표의 `DIRECT`, `LINKED`는 설명용 축약이다. 실제 생성 메타데이터에는 각각 공통 규격의 `DIRECT_RAW`, `LINKED_RESOLVED`를 사용한다. 문장에서 목적·사유를 발췌하면 `TEXT_EXTRACTED`, 원문값을 거래소·증권·사건 표준코드로 바꾸면 `DIRECT_NORMALIZED`, 여러 문장을 종합해 상장방식을 판단하면 `DERIVED_CLASSIFICATION`으로 구분한다.

## 5. Fact 사전

표의 Fact ID는 의미 단위 `factKey`다. `.raw`, `.code`, `.normalized`는 같은 Fact envelope의 원문값·표준코드·정규화값을 설명한다. 거래소명처럼 원문에 직접 있는 값은 `rawValue`로, `LONDON_STOCK_EXCHANGE` 같은 내부 표준명은 `normalizedValue`로 함께 보존한다.

### 5.1 사건 공통 Fact

| Fact ID | 의미 | 생성 | 원문 근거·조건 |
|---|---|---|---|
| `overseas_listing.event_action.raw` | 상장결정·상장완료·폐지결정·폐지완료라는 원문 사건명 | `DIRECT` | 공시 제목 |
| `overseas_listing.event_action.code` | `LISTING_DECISION`, `LISTING_COMPLETED`, `DELISTING_DECISION`, `DELISTING_COMPLETED` 중 표준 행위 | `DIRECT_NORMALIZED` | 제목과 서식 일치 |
| `overseas_listing.purpose` | 해외 상장·폐지의 공시상 목적 | `DIRECT` | 목적·기타사항 |
| `overseas_listing.decision_date` | 이사회 등 결정일 | `DIRECT_NORMALIZED` | 날짜 원문도 보존 |
| `overseas_listing.planned_date` | 상장·폐지 예정일 | `DIRECT_NORMALIZED` | 예정 상태 |
| `overseas_listing.actual_date` | 실제 상장·폐지일 | `DIRECT_NORMALIZED` 또는 `LINKED` | 완료공시에서 확인 |
| `overseas_listing.listing_mode.raw` | 신규발행·기존증권·구주매출·이전상장 방식의 원문 | `DIRECT` | 독립 기재 시 |
| `overseas_listing.listing_mode.code` | 방식의 표준 코드 | `DIRECT_NORMALIZED` 또는 `DERIVED_CLASSIFICATION` | 생성 근거를 함께 저장 |
| `overseas_listing.status.raw` | 예정·진행·완료·철회 상태 원문 | `DIRECT` | 상태 문구 |
| `overseas_listing.status.code` | 상태 표준 코드 | `DIRECT_NORMALIZED` | 완료공시 전 자동 완료 금지 |

사건행위 코드는 `LISTING_DECISION`(상장 결정, 아직 완료 전), `LISTING_COMPLETED`(실제 상장 완료), `DELISTING_DECISION`(폐지 결정, 아직 거래종료 전), `DELISTING_COMPLETED`(실제 폐지 완료), `UNKNOWN`으로 사용한다.

상장방식 코드는 다음처럼 원문 명시값과 복수 Fact 판정값을 구분한다.

| 코드 | 의미 | 판정조건 |
|---|---|---|
| `NEW_ISSUE_LISTING` | 신주를 발행해 해외상장 | 신주발행과 자금조달이 명시됨 |
| `EXISTING_SECURITY_LISTING` | 이미 발행된 증권을 해외상장 | 신주발행이 없고 이전상장도 아님 |
| `TRANSFER_LISTING` | 기존 거래소의 동일 증권을 다른 거래소로 이전 | 이전상장 문구 또는 폐지+신규상장 관계가 확인됨 |
| `ADDITIONAL_MARKET_LISTING` | 기존 해외시장을 유지하며 다른 시장에 추가상장 | 기존시장 유지 근거 필요 |
| `UNKNOWN` | 상장방식 확인불가 | 임의 분류 금지 |

원문에 “이전상장”이 직접 적히면 raw는 `DIRECT_RAW`, 코드는 `DIRECT_NORMALIZED`다. 폐지와 신규상장 공시를 종합해 이전상장을 판정하면 `DERIVED_CLASSIFICATION`이다.

| Fact ID | 의미 | 생성 | 원문 근거·조건 |
|---|---|---|---|
| `overseas_listing.trade_end_planned_date` | 상장폐지 대상 증권의 매매거래 종료 예정일 | `DIRECT_RAW` + 날짜 정규화 | 폐지결정 공시 |
| `overseas_listing.trade_end_actual_date` | 실제 매매거래 종료일 | `DIRECT_RAW` + 날짜 정규화 | 폐지완료 공시 |
| `overseas_listing.completion_confirmation_date` | 상장·폐지 완료가 확인된 공시일 | `SOURCE_METADATA` | 실제 사건일과 구분 |
| `overseas_listing.fundraising_status` | 회사 자금조달의 있음·없음·미확인 상태 | 명시값은 `DIRECT_NORMALIZED`, 복수 근거 판정은 `DERIVED_CLASSIFICATION` | 모집·매출·신주 문구 |
| `overseas_listing.fundraising_method.raw` | 공모·사모·구주매출 등 자금조달 방식 원문 | `DIRECT_RAW` | 모집·매출 방법 |
| `overseas_listing.fundraising_method.code` | 신주·구주·혼합·없음 표준 코드 | `DIRECT_NORMALIZED` | 원문 매핑 |

거래소와 증권의 “연결”은 계산이 아니라 어느 거래소에 어느 증권이 적용되는지 짝짓는 것이다. 최종 구조는 `security_refs[]`와 `market_refs[]`를 사용하지 않고 거래소 아래 `affected_securities[]`를 직접 둔다. 현대자동차처럼 런던에는 우선주 GDR만, 룩셈부르크에는 보통주·우선주·2우선주 GDR이 적용되는 경우를 잘못 합치지 않기 위해서다.

## 6. 결정적 계산 규칙

| 계산 ID | 공식 | 만든 이유 | 해석 한계 |
|---|---|---|---|
| `OVERSEAS_LISTED_SHARE_RATIO` | `해외상장 대상 원주 수(S) ÷ 동일 종류 발행주식 수(T) × 100` | 해외상장 대상의 상대적 수량을 답하기 위해 | 해외 투자자 보유비율이나 유통비율 확정이 아님 |
| `DR_UNDERLYING_SHARE_CHECK` | `DR 수(D) × DR당 원주 수(R)` | DR 수와 원주 수 환산 검산 | 비율 방향이 확인될 때만 |
| `GROSS_PROCEEDS_CHECK` | `발행·매출 증권 수(Q) × 증권당 가격(P)` | 총대금 산술검산 | 비용 차감 후 회사 순유입액이 아님 |
| `NET_PROCEEDS_REFERENCE` | `총조달액(G) − 공시비용(C)` | 공시된 비용 범위의 단순 순액 | 세금·추가비용 누락 시 확정 순현금 아님 |
| `SCHEDULE_CHANGE_DAYS` | `정정 후 예정일 − 정정 전 예정일` | 상장·폐지 일정 변화 답변 | 거래 성공·실패 판단이 아님 |
| `DR_COUNT_CHECK` | `기초 원주 수 × DR 비율 단위 ÷ 원주 비율 단위` | 공시 교환비율과 DR 수량 검증 | 공시값 검증식이며 표준기관 고정 ID가 아님 |
| `UNDERLYING_COUNT_CHECK` | `DR 수 × 원주 비율 단위 ÷ DR 비율 단위` | DR 수에서 기초 원주 수 역산 | 비율방향 확인 필요 |
| `UNDERLYING_COUNT_CHANGE` | `완료 기초 원주 수 − 결정 기초 원주 수` | 결정·완료 수량 변화 | 수량 기준일 차이 원인 단정 금지 |
| `DR_COUNT_CHANGE` | `완료 DR 수 − 결정 DR 수` | 결정·완료 DR 변화 | 보유자 매매량 아님 |
| `DR_COUNT_CHANGE_RATE` | `DR 수 변화 ÷ 결정 DR 수 × 100` | 수량 변화율 | 시장 수익률 아님 |
| `DECISION_TO_COMPLETION_DAYS` | `실제 완료일 − 결정일` | 결정부터 완료까지 경과일 | 법정 처리기한 아님 |
| `SCHEDULE_VARIANCE_DAYS` | `실제 완료일 − 예정일` | 예정 대비 조기·지연일수 | 성공·실패 판단 아님 |
| `DR_BACKING_SHARE_RATIO` | `DR 기초 예탁원주 수 ÷ 동일 종류 발행주식 수 × 100` | 전체 주식 중 DR 기초원주의 상대규모 | 외국인지분율·해외투자자 보유율·실제 유통량 아님 |
| `NEW_SHARE_DILUTION` | `신주 수 ÷ (기존 발행주식 수 + 신주 수) × 100` | 신주발행 시 기존주주의 기계적 상대희석 | 주가하락률 아님; 이전상장·구주매출에는 적용 금지 |

S·T·D·R·Q·P·G·C는 설명을 위한 지역 변수이며 업계의 고정 표준기호가 아니다. 구현에서는 각각 대응 Fact ID를 입력으로 사용한다.

### 6.1 계산 성격과 사용조건

`DR_COUNT_CHECK`·`UNDERLYING_COUNT_CHECK`는 공시가 제시한 원주:DR 비례관계를 산술 검증하는 식이다. 나머지 수량차이·일수·비중 계산 ID는 사용자 질문에 답하려고 프로젝트가 정의한 비교규칙이며 법정·공식 지표가 아니다. 모든 계산 결과에는 `formula_source=DISCLOSED_RATIO_VALIDATION` 또는 `PROJECT_DEFINED_COMPARISON`을 표시한다.

DR 비율 방향, 주식종류, 수량 기준일, `SHARE`와 `DR_UNIT` 단위를 확인하지 못하면 계산하지 않는다. 표의 `-`는 0으로 변환하지 않는다. `NEW_SHARE_DILUTION`은 신규발행이 명시된 경우만 수행하고 구주매출·기존 DR 이전상장·거래소 변경에는 수행하지 않는다.

### 6.2 질문별 해석 한계

| 질문 | 계산·판정 | 말할 수 있는 것 | 말하면 안 되는 것 |
|---|---|---|---|
| DR 수량이 맞아? | `DR_COUNT_CHECK` | 공시 교환비율과 표시수량의 산술 일치 | DR 가치·가격 적정성 |
| 결정 때와 완료 때 수량이 왜 달라? | 수량차이와 기준일 비교 | 얼마가 달라졌고 기준일이 다르다는 사실 | 차이의 원인을 근거 없이 단정 |
| 전체 주식 중 해외 DR 규모는? | `DR_BACKING_SHARE_RATIO` | 기초 예탁원주의 상대적 규모 | 외국인지분율·실제 해외보유율 |
| 기존주주가 희석돼? | `NEW_SHARE_DILUTION` | 신주발행 시 기계적 상대희석 | 같은 비율의 주가하락 |
| 예정일보다 늦었어? | `SCHEDULE_VARIANCE_DAYS` | 실제일과 예정일의 날짜차이 | 지연이 부정적이라는 투자판단 |

### 6.3 근거·답변 상태

거래소별 대상증권, 증권명·주식종류, 원주·DR 수량과 기준일, 교환비율 방향, 결정·예정·실제일, 폐지사유, 보유자 조치, 자금조달 여부, 관련공시 관계를 원문 위치와 함께 보존한다.

| API 상태 | 판정 기준 |
|---|---|
| `COMPLETED` | 질문에 필요한 거래소별 증권·행위·수량 또는 상태·근거가 모두 확인됨 |
| `PARTIAL` | 핵심 일부는 확인했지만 완료공시·비율방향·다른시장 유지 등 필수항목이 부족 |
| `UNANSWERABLE` | 제공 공시에서 핵심정보를 찾을 수 없음 |
| `FAILED` | 검색·파싱·관계해결·계산 시스템 실패 |

## 7. 골든 후보

아래 네 문서는 삼성전자 공식 IR 자료로 사건 관계를 교차검증한 `C 검토대기` 후보다. 같은 삼성전자 우선주 DR 프로그램이 룩셈부르크 시장에서 폐지되고 런던 시장에 상장된 **시장 이전 묶음**으로도 연결해야 한다.

### GOLD-OVERSEAS-001: 삼성전자 해외상장 결정→완료

- 결정공시 접수번호: `20241031000536`
- 완료공시 접수번호: `20250213001817`
- 기대 행위: 첫 문서는 `LISTING_DECISION`, 둘째는 `LISTING_COMPLETED`.
- 기대 연결: `DECISION_TO_COMPLETION`으로 두 접수번호를 연결한다.
- 대상: 삼성전자 우선주 DR의 런던증권거래소 상장. 독립적인 신규 자금조달로 단정하지 않는다.
- 필수 검증: 거래소명·대상 증권명은 원문 그대로 저장하고 별도 표준 코드를 만든다. 결정일·예정일·실제일을 혼용하지 않는다.
- 치명적 오류: 결정공시만으로 실제 상장 완료 처리, 거래소 원문을 코드로 덮어쓰기, DR과 원주 수량 혼용.

### GOLD-OVERSEAS-002: 삼성전자 해외상장폐지 결정→완료

- 폐지결정 접수번호: `20241031000508`
- 폐지완료 접수번호: `20250213001808`
- 기대 행위: `DELISTING_DECISION` → `DELISTING_COMPLETED`.
- 대상: 같은 삼성전자 우선주 DR의 룩셈부르크증권거래소 상장폐지.
- 필수 답변: 폐지 대상 해외시장·증권과 실제 폐지일을 근거로 제시하고 국내 상장 유지 여부는 별도 Fact가 있을 때만 답한다.
- 치명적 오류: 해외 특정 증권의 폐지를 삼성전자 전체 상장폐지로 표현.

두 후보 사이에는 `SAME_SECURITY_MARKET_TRANSFER` 관계를 별도로 둔다. 이는 각각의 결정→완료 관계를 대체하는 것이 아니라, 동일 DR이 룩셈부르크에서 런던으로 이전됐다는 경제적 관계를 표현한다.

### GOLD-OVERSEAS-003: 카카오 싱가포르 GDR 상장폐지

- 결정공시 후보 접수번호: `20230511000691`.
- 완료공시 후보 접수번호: `20230525000446`.
- 검증 목적: 결정→완료 관계, 싱가포르 거래소, 대상 GDR, 실제 폐지일, DR 보유자 조치.
- 기대 처리: 완료공시의 관련 공시일·공시명을 이용해 결정공시 접수번호를 `LINKED_RESOLVED`로 찾고 `relation_type=DECISION_TO_COMPLETION`을 부여한다.
- 금지 표현: 싱가포르 GDR 폐지를 카카오 국내 주식 전체 상장폐지로 표현.
- 승인상태: `C_REVIEW_PENDING`; 증권명·수량·보유자 조치 원문 위치를 대회 파일에서 확정.

### GOLD-OVERSEAS-004: SK텔레콤 런던 DR 폐지와 뉴욕 유지

- 검증 목적: 한 해외시장 폐지와 다른 해외시장 유지 상태를 동시에 반환한다.
- 기대 Fact: 런던 대상 DR과 폐지상태, 뉴욕의 유지되는 증권·시장, 각 근거.
- 기대 답변: “런던시장 대상 DR의 폐지는 확인되지만, 다른 해외시장 상장까지 모두 폐지된다는 의미는 아닙니다.”
- 치명적 오류: 런던 폐지를 모든 해외상장 폐지로 합치거나 국내 상장폐지로 답변.
- 승인상태: `C_REVIEW_PENDING`.

### GOLD-OVERSEAS-005: 현대자동차 복수 거래소·복수 GDR

- 검증 목적: 거래소별 대상증권 범위를 `affected_securities[]`로 정확히 보존한다.
- 기대 관계: 런던에는 우선주 GDR, 룩셈부르크에는 보통주·우선주·2우선주 GDR이 대응되는 사례를 원문 기준으로 검수한다.
- 기대 용어처리: 2우선주를 배당·청산의 “2순위” 주식으로 해석하지 않는다.
- 치명적 오류: 두 거래소에 모든 증권이 동일하게 적용된다고 답하거나 원주·DR 수량을 합산.
- 승인상태: `C_REVIEW_PENDING`.

### 7.1 공통 치명적 오류

1. 상장결정·폐지결정을 실제 완료로 처리.
2. 실제 상장·폐지일과 공시 접수일을 혼용.
3. 거래소 원문명을 내부 코드로 덮어씀.
4. 거래소가 여러 곳일 때 대상증권 범위를 합침.
5. 원주 수와 DR 수를 같은 단위로 합산.
6. 원주:DR 비율 방향을 뒤집음.
7. 2우선주를 자동으로 경제적 2순위 우선주로 해석.
8. 구주매출을 회사 신주발행·직접 자금조달로 처리.
9. 기존 DR 이전상장을 신주발행이나 구주매출로 처리.
10. 신주가 없는데 희석률 계산.
11. DR 기초원주 비율을 외국인지분율·해외투자자 보유율로 표현.
12. 특정 해외시장 폐지를 모든 해외시장·국내시장 상장폐지로 확대.
13. 관련공시 후보만으로 문서관계를 확정하고 최신상태를 덮어씀.
14. 해외상장·폐지를 근거로 주가방향이나 투자권유를 제시.

## 8. B의 구현 순서

1. 제목에서 사건 행위의 원문과 표준 코드를 만든다.
2. 거래소와 증권을 각각 배열로 추출하고 시스템 식별자를 부여한다.
3. 원문 관계표를 바탕으로 거래소↔증권 연결을 한 방향에서 생성하고 역참조를 검증한다.
4. 원문 거래소명·증권명·수량을 보존한 채 코드·표준 수량을 별도 생성한다.
5. 결정·정정·완료·장기적으로 폐지 공시를 접수번호로 연결한다.
6. DR 환산·비중·대금 계산은 단위와 비율 방향이 확인될 때만 수행한다.
7. C가 승인한 다섯 골든 후보로 결정/완료, 시장이전, 거래소별 증권범위, 해외/국내, DR/원주 분리를 회귀검증한다.
