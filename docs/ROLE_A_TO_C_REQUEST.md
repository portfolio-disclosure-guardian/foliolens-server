# 역할 A → 역할 C: 첫 수직 슬라이스 금융 정책 승인 요청

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.1 |
| 요청일 | 2026-08-26 |
| 문서 상태 | `REQUEST` · `DECISION_REQUIRED` |
| 요청자 | 역할 A |
| 최종 의미 승인 | 역할 C |
| 구현 가능성 검토 | 역할 B |
| 대상 | SK하이닉스 신규시설투자 공시 `20240424800596` |

> 이 문서는 역할 C에게 tool enum, QueryPlan DTO 또는 검색 코드를 설계해 달라고 요청하지 않는다. 역할 C는 질문에 필요한 금융 fact·근거·계산·판정·표현 기준을 승인하고, 역할 A는 이를 기존 5개 tool의 실행 계약으로 변환하며, 역할 B는 실제 데이터와 구현 가능성을 검증한다.

## 1. 요청 결론

역할 C는 첫 수직 슬라이스에 사용할 versioned `AnswerPolicy` 또는 동등한 불변 fixture 한 건을 승인해 주세요.

승인 범위는 다음 여섯 묶음이다.

1. 필수 fact와 fact별 최소 evidence
2. 계산 공식·단위·반올림·허용 오차
3. 정상 답변의 완료·부분·답변 불가 기준
4. claim별 근거 연결 기준
5. 허용·금지 표현
6. 기대 결과와 근거가 포함된 골든 케이스 1건

전체 공시 유형이나 관심사 9종의 정책은 이번 요청 범위가 아니다. 첫 공시 한 건의 승인 계약이 실제로 동작한 뒤 확장한다.

## 2. 역할 경계

| 범위 | 역할 A | 역할 B | 역할 C |
|---|---|---|---|
| plan-facing tool 목록·step·검증 | 최종 책임 | 구현 가능성 검토 | 금융 요구사항 검토 |
| fact·evidence 의미 | 답변 연결 | 추출·원문 위치 구현 | 필수 항목·최소 근거 승인 |
| 계산 | 호출·결과 연결 | 결정적 계산 구현 | 공식·비교 가능성·반올림 승인 |
| 답변 판정·표현 | 정책을 기계적으로 집행 | 사용 근거 제공 | 의미·완전성·안전 기준 승인 |
| 골든 케이스 | 자동 실행 | 검색·계산 fixture | 질문·기대값·판정 소유 |

역할 C의 이번 범위에서 제외한다.

- `ToolType` 이름 추가·변경
- `QuestionPlan`·`PlanStep` Java DTO 설계
- 검색·파싱·계산 구현
- timeout·retry·실행 상태·평가 API 오류 계약
- 전체 공시 유형용 범용 규칙 엔진

> SK하이닉스가 2024년 4월 발표한 신규시설투자의 투자금액과 목적은 무엇이고, 자기자본 대비 비율은 맞는가?

| 항목 | 값 |
|---|---|
| 접수번호 | `20240424800596` |

| 공시 유형 | `신규시설투자등` |

| 평가 데이터 | 대회 `CONTEST` 코퍼스 |

## 4. C에게 요청하는 결정

### 4.1 필수 fact와 최소 evidence

아래 8개 fact는 첫 수직 슬라이스의 추출 대상이다. 역할 C는 각 fact의 **답변 필수도**를 `REQUIRED`, `SUPPORTING`, `NOT_USED` 중 하나로 정하고, 해당 값을 인정하기 위한 최소 evidence를 작성해 주세요.

| factKey 제안 | 원문 레이블 | 질문에서의 용도 | 답변 필수도 | 최소 evidence |
|---|---|---|---|---|
| `facility.target` | 투자대상 | 대상 식별 | C 작성 | C 작성 |
| `facility.amount` | 투자금액(원) | 직접 답변·계산 분자 | C 작성 | C 작성 |
| `facility.equity_amount` | 자기자본(원) | 계산 분모 | C 작성 | C 작성 |
| `facility.equity_ratio` | 자기자본대비(%) | 공시값과 재계산값 비교 | C 작성 | C 작성 |
| `facility.purpose` | 투자목적 | 직접 답변 | C 작성 | C 작성 |
| `facility.start_date` | 투자기간 시작일 | 기간 보조 정보 | C 작성 | C 작성 |
| `facility.end_date` | 투자기간 종료일 | 기간 보조 정보 | C 작성 | C 작성 |
| `facility.decision_date` | 이사회결의일(결정일) | 기준시점 보조 정보 | C 작성 | C 작성 |

최소 evidence에는 적어도 다음 추적 정보가 있어야 한다.

- 실제 `CONTEST` 원문 문서 식별자와 접수번호
- section·table·row 또는 동등한 원문 위치
- 원문 레이블·값·단위가 함께 보이는 인용 구간
- fact가 정정·후속공시의 영향을 받는 경우 그 관계와 기준시점

추가 승인 사항:

- [ ] `facility.*`를 표준 namespace로 사용할지 결정
- [ ] 기존 문서의 `investment.*`와 병합·교체할지 결정
- [ ] namespace 결정은 역할 B의 저장·추출 가능성 검토 후 승인
- [ ] 승인 전 silent alias나 중복 저장을 허용하지 않음

### 4.2 계산 정책

기준 계산식 제안은 다음과 같다.

```text
자기자본 대비 비율(%) = 투자금액 / 자기자본 × 100
```

역할 C는 다음 항목을 확정해 주세요. 값이 부족해 결정할 수 없으면 추측하지 말고 `판단 불가`와 필요한 추가 정보를 적는다.

| 결정 항목 | C 승인값 |
|---|---|
| 계산에 사용할 분자 fact | C 작성 |
| 계산에 사용할 분모 fact | C 작성 |
| 허용 단위와 단위 변환 조건 | C 작성 |
| 분모가 0·음수·누락일 때 처리 | C 작성 |
| 계산에는 원문값·정규화값 중 무엇을 사용할지 | C 작성 |
| 표시 소수 자릿수 | C 작성 |
| 반올림 방식 | C 작성 |
| 공시 기재 비율과 재계산값의 허용 오차 | C 작성 |
| 허용 오차를 넘는 경우의 판정 | C 작성 |
| 공시값과 재계산값 중 답변에 우선 표시할 값 | C 작성 |

승인 전에는 역할 A와 B가 임의의 반올림·허용 오차를 기본값으로 고정하지 않는다.

### 4.3 정상 답변 충족도

아래 명칭은 의미 합의를 위한 작업 용어이며 Java enum 이름 확정 요청이 아니다.

| 작업 용어 | 제안 의미 | C 결정 |
|---|---|---|
| `COMPLETED` | 기준 질문의 모든 필수 항목과 계산을 충분한 근거로 답함 | 승인·수정 |
| `PARTIAL` | 일부 필수 항목은 답할 수 있으나 하나 이상이 누락되거나 검증되지 않음 | 승인·수정 |
| `UNANSWERABLE` | 정상 검색·검증을 마쳤지만 코퍼스 근거로 기준 질문의 핵심을 답할 수 없음 | 승인·수정 |

`FAILED`는 timeout, DB·파서·HCX 오류 등 실행 실패를 나타내는 역할 A의 실행 상태다. 역할 C에게 금융적 답변 충족도 상태로 정의해 달라고 요청하지 않는다.

역할 C는 특히 다음 경계를 승인해 주세요.

- 투자금액은 확인되지만 투자목적이 없을 때의 판정
- 투자금액·자기자본은 있으나 공시 기재 비율이 없을 때의 판정
- 공시 기재 비율과 재계산값이 허용 오차를 넘을 때의 판정
- 값은 있으나 단위나 원문 근거가 불명확할 때의 판정
- 질문 대상 공시가 정정·후속공시로 변경됐을 때 사용할 기준

### 4.4 claim별 근거 연결

다음 최소 규칙을 승인하거나 수정해 주세요.

| claim 유형 | 최소 근거 제안 | C 결정 |
|---|---|---|
| `FACT` | 검증된 fact와 해당 원문 evidence | 승인·수정 |
| `CALCULATION` | 계산 기록, 공식, 모든 입력 fact와 각 evidence | 승인·수정 |
| `INTERPRETATION` | 사용한 fact·evidence와 불확실성 또는 한계 표현 | 승인·수정 |

추가 원칙:

- 한 evidence가 여러 fact를 뒷받침할 수 있으나 각 연결을 명시한다.
- 모델이 생성한 요약문은 원문 evidence로 인정하지 않는다.
- 누락 fact를 0으로 바꾸지 않는다.
- 답변에 사용하지 않은 evidence를 핵심 근거처럼 표시하지 않는다.

### 4.5 허용·금지 표현

역할 C는 아래 공통 원칙을 승인하고, 시설투자 공시에 필요한 추가 표현 규칙을 작성해 주세요.

허용 표현 제안:

- `해당 공시 기준으로 확인됩니다.`
- `공시 기재 비율은 X이며, 원문 금액으로 재계산한 값은 Y입니다.`
- `허용 오차 기준 안에서 일치합니다.`
- `근거가 부족하여 해당 항목은 확인할 수 없습니다.`

금지 표현 제안:

- 매수·매도 권유, 목표주가, 상승·하락 확률, 수익 보장
- 시설투자만으로 실적·주가 상승을 단정하는 인과 표현
- 공시에 없는 자금조달 방식·생산능력·완공 효과를 추정하는 표현
- 불일치한 비율을 근거 없이 오류나 허위공시로 단정하는 표현
- `CONTEST` 외부 데이터로 빈 값을 보충했다는 표현

추가 규칙은 다음 형식으로 작성한다.

| 코드 | 허용/금지 | 규칙 | 허용 예시 | 금지 예시 |
|---|---|---|---|---|
| C 작성 | C 작성 | C 작성 | C 작성 | C 작성 |

## 5. 승인 완료 조건

다음 항목이 모두 충족되면 역할 C의 첫 수직 슬라이스 입력을 승인 완료로 본다.

- [ ] 8개 fact의 답변 필수도와 최소 evidence가 정해짐
- [ ] 계산 공식·단위·반올림·허용 오차가 정해짐
- [ ] `COMPLETED`·`PARTIAL`·`UNANSWERABLE` 의미가 정해짐
- [ ] FACT·CALCULATION·INTERPRETATION의 근거 규칙이 정해짐
- [ ] 시설투자 허용·금지 표현이 정해짐
- [ ] 골든 케이스 1건의 기대값과 원문 위치가 채워짐
- [ ] `facility.*`·`investment.*` namespace를 역할 B와 공동 승인함
- [ ] `policyVersion`이 부여됨

## 6. 회신 방식과 후속 작업

역할 C는 각 `C 작성`·`승인·수정` 셀을 채우고, 결정할 수 없는 항목은 `판단 불가`와 필요한 추가 자료를 적는다.

승인 후 역할별 후속 작업은 다음과 같다.

1. 역할 A: 승인 내용을 기존 5개 tool의 구조화 입력·validator·답변 검증에 반영
2. 역할 B: 동일 계약으로 실제 HTML fact·evidence 추출과 결정적 계산 구현
3. 역할 C: 골든 케이스 결과와 금융 표현 최종 검수

역할 A는 C의 승인을 기다리는 동안 동일 경계 DTO의 고정 fake로 오케스트레이션과 평가 API 계약을 진행한다. 승인되지 않은 금융 규칙을 실제 답변 판정에 사용하지 않는다.
